# 只读 Agent 对话分析设计规格

日期：2026-08-12
状态：完整设计已确认，等待书面规格审阅；尚未实施

## 1. 背景与当前基础

每日数据审核与可视化平台已经具备导入、人工审核、版本化发布、已发布数据看板、备份恢复和服务器容器部署能力。数据准确性仍由现有业务闭环保证：原始文件先解析为草稿，人工对照并修正，完整校验后才发布；任何后续修改都通过新修订重新审核和发布，历史版本不被覆盖。

当前仓库已经存在三个数据库无关的只读 Agent 工具边界：

- `published_summary`
- `product_performance`
- `return_breakdown`

它们位于 `backend/app/agent_tools/service.py`，并委托 `backend/app/analytics/service.py` 查询已发布数据。当前尚未接入 LangChain、DeepSeek、Agent 运行任务、对话 API 或 Agent 页面。

本里程碑命名为“阶段 11A：只读 Agent 对话分析”。它在现有发布数据之上增加一个独立分析页面，让所有已登录用户用自然语言查询已发布经营与退货数据。该功能不能降低既有审核、版本和权限边界，也不能形成任何自动写数据路径。

## 2. 目标

阶段 11A 需要实现：

1. 为所有已登录用户提供独立的 `/agent` 分析页面，包括 `viewer`。
2. 使用 LangChain 的 DeepSeek 聊天模型适配器和工具绑定能力，首版不引入 LangGraph 执行图。
3. 每次运行只分析用户当前站点以及本次运行开始时冻结的已发布数据和站点配置版本。
4. 让服务端生成并校验所有业务数字、日期、指标卡、图表和版本引用；模型不能成为数值真相来源。
5. 回答能精确追溯到报告日期、报表类型、数据集、发布版本、发布时间和站点配置版本。
6. 当回答暴露潜在数据问题时，引导有权限的人员进入现有“创建修订 → 人工审核 → 完整校验 → 发布”闭环。
7. 将模型运行与主应用隔离，使 Agent Runtime 不持有 MySQL 凭据，也不能访问原始文件、备份、密钥目录或业务写服务。
8. 保留短期个人对话以方便使用，同时限制内容留存和备份范围。
9. 记录用量和可计算费用并提供告警，不设置每日或每月金额硬上限。
10. 保留明确的 `AgentRuntime` 抽象，使后续可以在不改变 API、数据校验和工具安全边界的前提下替换为 LangGraph 实现。
11. 将“对话”限定为用户界面的运行历史分组；每个问题都独立分析，不把旧问题、旧回答或旧事实重新发送给模型。

## 3. 非目标

首版不包含：

- 读取草稿、原始 CSV、解析源行、失败批次、内部备注、订单号或买家留言原文。
- 编辑、补全、发布、回滚、跨日期移动或删除业务数据。
- 自动创建修订或自动应用“纠错建议”。
- 任意 SQL、数据库浏览、文件访问、代码执行、联网搜索或第三方业务工具。
- 日报、定时分析、通知、邮件或外部导出。
- 用户反馈、回答评分、长期知识库、向量检索或跨用户记忆。
- 依赖上一轮自然语言指代的上下文对话；“那个 SKU”“继续分析上一个结果”等问题必须由用户补全对象和范围后重新运行。
- 模型切换、模型参数调节、提示词编辑或面向普通用户的费用配置。
- 由 Agent 判断原表格是否真实；Agent 只能说明它已经对照系统中固定的已发布版本。
- 把模型相关性解释包装为已证明的因果结论。

## 4. 核心原则与术语

### 4.1 已发布数据是唯一业务输入

Agent 只读取当前发布层在运行开始时对应的不可变版本。草稿、原始层、历史版本和内部备注即使存在，也不能进入工具结果、模型请求、回答、日志或管理员用量页面。

“已发布”不代表业务世界中的绝对真相。页面统一使用“已对照固定发布数据”等表述，不能声称“数据绝对正确”。若发布数据与原表一致但业务方仍希望调整，仍必须由人工创建修订并保留审计。

### 4.2 分析范围、站点与运行快照

页面中的日期称为“分析范围”，起止日均包含。一次运行只属于当前应用站点，创建请求携带页面从服务端站点上下文取得的 `site_id`；后端要求它与请求时重新解析出的当前活动站点精确相等，不能仅凭调用方提交的站点处于活动状态就接受。首版不提供跨站点合并，因此也不产生跨币种合计。

一次运行使用一个不可变 `run snapshot manifest`，固定：

- `site_id`、用户选择的分析范围和该站点当时的 `site_config_version_id`、时区及币种。
- `report_date_publications`：该站点报告日在分析范围内的每个当前已发布每日数据集，包括 `dataset_id`、报表类型、`version_id` 和 `published_at`。
- `event_date_return_candidate_publications`：该站点在快照时刻的全部当前已发布退货版本，包括 `dataset_id`、报告日、`version_id` 和 `published_at`。这是事件日查询必须完整扫描的 coverage universe；即使某个版本没有活动行落入分析事件日范围，也不能从清单省略。候选版本的报告日可以位于分析范围之外。
- 完整的报告日期期望网格 `{site_id, report_type, report_date, currency}`，包括没有发布版本的单元格。
- 运行时版本、模型配置、提示词版本、工具 schema 版本、维度规范化版本、隐私规则版本和校验器版本。
- 清单规范化后的 SHA-256。

事件日集合必须保留现有看板语义。例如 8 月 5 日报告中包含 8 月 1 日退货事件时，分析 8 月 1 日事件日必须冻结并扫描 8 月 5 日的当前已发布退货版本，不能因为其报告日在范围外而漏数。事件日工具的 `coverage publication references` 必须与全部候选版本精确相等；`matching publication references` 是至少一条活动行在冻结配置与时区下经过安全 UTC envelope 预筛及精确本地日期复核后命中范围的候选版本子集；每个 fact 的 `contributor publication references` 则精确等于真正参与该 fact 聚合的 matching 版本，可以为空。截断或 top-N 会使 matching 集合大于页面已展示 facts 的 contributor 并集，不能把二者强行等同。这样零结果也能证明所有候选版本均已扫描。

快照捕获使用专用连接，先设置 `REPEATABLE READ`，再执行 `START TRANSACTION WITH CONSISTENT SNAPSHOT`；第一次一致性读之前不执行其他读取，捕获期间的所有查询均为 nonlocking consistent read，不得使用 `SELECT ... FOR UPDATE`、`SELECT ... FOR SHARE` 或其他破坏同一快照语义的 locking read。若改用一个能同时返回上述指针、配置和候选版本的等价原子语句，必须通过同样的并发 oracle。不能依赖当前默认的 `READ COMMITTED` 多语句事务。并发发布、回滚和配置切换测试必须证明清单只对应同一个事务边界。

旧运行永远引用自己的快照。后续发布、回滚或站点配置变化不会改写旧回答；新运行才捕获新的版本。

### 4.3 服务端事实

`fact` 是后端从冻结快照确定性计算的最小可引用事实。规范结构固定包含：

```text
fact_id
metric / entity
value
unit / currency
period
dimensions
completeness / coverage
basis
snapshot_id
matching publication references
contributor publication references
coverage publication references
site configuration version references
```

金额以十进制字符串传输，计数使用整数，比例明确分母和空值语义。`matching references` 是命中本次事件日查询范围的版本，`contributor references` 是实际贡献该 fact 数值的版本，`coverage references` 是证明该工具在投影范围内完整读取的版本集合；三者不能混用，且 `contributor ⊆ matching ⊆ coverage`。报告日工具不需要独立 matching 集合，其 contributor 仍必须是 coverage 的可复算子集。

`claim` 是后端从 facts 预先计算的关闭式陈述。首版只允许 `metric_value`、`difference`、`ratio`、`rank`、`trend_direction`、`availability` 和 `coverage_warning`。每个 claim 都有不可变 `claim_id`、类型、fact operands、适用条件和服务端模板。展示的每个业务数字、实体、排名、比较方向、日期、单位、覆盖状态和版本引用都来自已验证 claim；模型不能创建新的 operands 或自然语言事实。

对于“为什么下降”等因果问题，首版只能展示同时期的已验证事实，并用固定模板说明“现有发布聚合不能证明原因”；不能让模型把相关性写成因果关系。

### 4.4 安全失败

当模型、工具、版本、引用或校验出现不确定性时，运行明确失败并给出可操作的规范化错误。系统宁可不回答，也不能展示猜测数字、混合版本或未校验的部分答案。

## 5. 总体架构

```text
React /agent 页面
        │ 同源 Session + CSRF + JSON/SSE
        ▼
FastAPI 主后端
  ├─ Agent API、对象级授权、幂等与并发门禁
  ├─ 对话/运行/事件/用量持久化
  ├─ 快照清单捕获
  ├─ 独立 agent_reader engine + snapshot-scoped 查询器
  ├─ 三个工具的严格 schema 与额度控制
  ├─ 事实生成、结构校验和安全渲染
  └─ 内部 Agent Runtime 协议
        │ 仅 agent_control 内部网络
        ▼
独立 Agent Runtime
  ├─ AgentRuntime 接口
  ├─ LangChain ChatDeepSeek.bind_tools
  ├─ 显式受限工具循环
  └─ DeepSeek API Key
        │ HTTPS 出站
        ▼
DeepSeek API
```

### 5.1 FastAPI 主后端职责

主后端是所有业务事实和权限的权威边界。它负责：

- 校验登录、角色、资源所有权、CSRF 和幂等键。
- 在接受运行时原子分配用户和全局容量，并创建运行快照。
- 持久化任务、租约、事件和最终答案。
- 接收 Runtime 的工具请求，重新校验工具名、参数、调用次数、绝对截止时间和快照归属。
- 使用独立 `agent_reader` 数据库连接池和快照限定查询器执行三个只读工具。
- 把工具结果转换为规范化 facts 和关闭式 claims，并验证 Runtime 返回的展示选择。
- 生成指标卡、图表、日期、覆盖状态和不可伪造的站内引用链接。
- 在终态后精确累计一次用量。

Agent 任务、事件和用量使用主应用 engine 持久化；业务查询必须使用第二个 `agent_reader` engine，连接或权限失败时安全失败，禁止回退到主 engine。Alembic 只创建或升级包含允许字段的安全视图：已发布指针、不可变版本、活动经营行、退货事件时间及允许的规范化聚合维度、站点配置版本。视图固定使用版本控制的稳定 `DEFINER` 与 `SQL SECURITY DEFINER`；生产和恢复流程必须先保证 definer 生命周期，再验证视图可解析。视图不包含草稿、原始值、订单号、买家留言、物流牌照、备注或审计内容。

数据库账号生命周期不由 Alembic 承担。现有 root 级 bootstrap/deployment privilege synchronizer 负责创建和轮换 `clsen_agent_reader`、先撤销漂移授权，再按版本化权限清单仅授予安全视图的 `SELECT`；账号没有基础表权限和任何写权限。该账号的 Secret、Compose 注入、权限 manifest 及解析器、CI MySQL 8.0/8.4、本地矩阵、部署和恢复验证必须同步更新，并用 `SHOW GRANTS` 正反向核对实际授权。主后端不会把 SQL、数据库连接、业务写服务或草稿读取接口暴露给 Runtime。

### 5.2 Agent Runtime 职责

Runtime 是独立进程或容器，只负责模型编排：

- 通过内部协议领取已授权任务。
- 将受控系统提示、当前用户问题、运行范围和允许的已发布聚合 facts/claims 发送给 DeepSeek；不发送该对话的历史问题、回答或旧快照事实。
- 使用 LangChain `ChatDeepSeek.bind_tools` 让模型在三个工具中选择。
- 执行显式工具循环，并把每次工具请求交回 FastAPI。
- 返回只引用已知 `claim_id` 的结构化展示计划和供应商 usage 元数据。

Runtime 不连接 MySQL，不读取任何应用业务内容目录，不生成站内引用 URL，也不直接向浏览器发送模型 token。它只能读取镜像内运行文件和明确挂载的 DeepSeek/mTLS secret。

### 5.3 运行时抽象与 LangChain 选择

后端定义稳定的 `AgentRuntime` 接口。首个实现为 `LangChainDeepSeekRuntime`，使用 LangChain 的模型消息、工具 schema 和 `bind_tools`，但自行实现有限状态循环。

首版不使用 `create_agent`，因为当前 LangChain agent 高层执行器依赖 LangGraph，会提前引入图状态、checkpoint 和额外运行语义。显式循环更容易审计工具次数、超时、事实校验和失败边界。

未来升级为 `LangGraphRuntime` 时，必须继续服从同一个运行快照、内部工具协议、事实 schema、API、权限、留存和验收门禁。LangGraph 不能获得新增数据权限，也不能绕开后端校验器。

## 6. 冻结快照与只读查询

### 6.1 捕获方式

运行创建流程根据用户明确选择的 `site_id`、`from_date` 和 `to_date`，在第 4.2 节规定的一致性快照中捕获：

1. 当前站点和具体站点配置版本。
2. 报告日范围内的发布指针和完整期望网格。
3. 捕获该站点全部当前已发布退货版本作为 `event_date_return_candidate_publications`；按冻结配置时区把用户事件日范围转换为 UTC 半开区间，但不以是否命中活动行过滤候选版本。
4. 快照清单及其哈希。

容量分配、用户/对话活动占位和任务创建使用主 engine 的独立短事务。只有快照捕获成功且哈希固定后才提交运行；任一步失败会释放占位，不能留下没有完整清单的任务。由于快照读和任务写使用权限隔离的两个 engine，实现必须用显式预留状态和补偿终结来闭合失败窗口，不能宣称它们是一个跨连接数据库事务。

事务只用于捕获清单和创建运行，不持续覆盖最长 90 秒的模型执行。

### 6.2 snapshot-scoped reader

当前 `PublishedAnalyticsQueryService` 每次查询都会重新联接 `dataset_publications` 当前指针，并且有意不接受调用方指定的 `version_id`。如果三个工具直接复用它，运行中发布 V2 时可能让不同工具混用 V1 和 V2。

因此阶段 11A 必须新增内部 `snapshot-scoped reader`：

- 只接受由后端从 `run snapshot manifest` 构造的版本集合，模型和 Runtime 不能提交 `version_id`。
- 每个查询都按清单中的版本和配置读取不可变行。
- 对每次工具调用，后端确定性计算 `expected_refs = project(manifest, tool, subrange, basis, site, currency)`；查询执行器必须记录并返回实际扫描的版本身份，校验器要求实际 coverage references 与 `expected_refs` 精确相等，禁止把 manifest 引用事后直接回填成 coverage 来掩盖漏读。每个 fact 的 contributor references 必须是其中可复算的精确子集。
- 对于事件日口径，在没有经过验证且不可变的逐版本时间边界元数据前，任何子范围的 `expected_refs` 都恒等于清单中的全部 `event_date_return_candidate_publications`，不能从查询实际命中行反推或缩小。查询先用兼容夏令时折叠/跳跃的安全 UTC envelope 预筛，再把每个时间戳转换到冻结 IANA 时区进行精确本地日期复核；matching references 由复核结果确定。
- 缺失、越界或不属于清单的版本导致运行安全失败。
- 普通看板仍可继续使用当前发布查询服务；不能为 Agent 破坏其“总是查询当前发布”的合同。

`site_config_versions` 一旦成为当前配置、发布版本引用或 Agent 快照引用，就属于 append-only 业务版本。数据库触发器拒绝普通账号对其执行 `UPDATE`/`DELETE`，迁移账号也不能用就地修改业务行完成升级；迁移或灾备若需修复只能通过受控、可审计流程并重新通过旧运行重放验证。Agent 读取固定配置 ID 后，其时区、币种和其他口径字段必须保持不变。

不采用“运行结束检查指针是否变化后仍接受结果”的弱方案，也不依赖持续数据库事务。只要清单中的不可变版本仍存在，旧运行就可以稳定完成和重放。

### 6.3 日期、缺失和币种语义

- 用户必须显式选择当前站点和分析日期范围，起止日均包含，最长 366 天。
- 工具只能查询该范围或其子范围，不能由模型扩大范围。
- 报告日完整性按冻结网格 `{site_id, report_type, report_date, currency}` 逐格计算。两类报表在整个范围均无发布时返回 `no_data`；某一类全无发布时该类为 `unavailable`；部分网格缺失时返回 `partial_data`、精确缺失单元格和覆盖范围。不得把缺失解释为 0，也不得做需要完整同期数据的比较。
- 已发布且真实为 0 的事实显示 0，并携带对应版本引用。
- 分母为 0 时比例为 `null / N/A`，不是 `0%`。
- 首版一次运行只有一个站点和一个冻结币种。将来若允许多站点，不同币种必须拆分，不能直接合计。
- 事件日计算必须引用具体统计时区和站点配置版本；缺失或非法时区时失败关闭。
- 事件日范围的 coverage references 是第 4.2 节捕获且查询执行器证明已实际扫描的全部候选版本；matching references 是实际有活动行命中范围的版本；每个 fact 的 contributor references 是实际参与该事实的 matching 版本，可以为空。coverage 只能证明已完整扫描冻结时刻的当前发布集合，不能证明尚未被未来报表记录的退货事件为 0；页面固定显示这一数据水位限制，模型不能省略。零命中只能由模板表述为“冻结发布集合中记录为 0/无命中”，不能宣称未来也不会出现退货事件。

## 7. 工具合同与执行额度

首版精确暴露三个工具，公开方法集合不能多于以下列表：

### 7.1 `published_summary`

查询选定范围内的已发布经营和退货汇总、覆盖情况、版本及站点配置引用。输入只包含范围内起止日期。

### 7.2 `product_performance`

查询已发布商品表现。输入包含范围内起止日期和 `limit`，其中 `1 <= limit <= 200`。排序、并列和截断状态由后端确定性定义并返回。

### 7.3 `return_breakdown`

查询已发布退货分解。输入包含范围内起止日期以及 `report_date` 或 `event_date` 口径。事件日响应必须包含统计时区与配置版本。

### 7.4 统一限制

- 所有输入使用关闭式 schema，拒绝额外字段、未知枚举、`raw_sql`、路径、URL、草稿标志或调用方版本 ID。
- 一次运行最多接受 6 次工具尝试；重复、并行、失败和非法尝试都计数，第 7 次直接终止运行。
- 一次运行从 API 接受请求到持久化终态的绝对截止时间为 90 秒，模型、工具、重试和校验均包含在内。
- 一次运行最多发起 7 次模型调用（首次调用加最多 6 次工具结果续接），最多 32,000 个输入 token 和 4,096 个输出 token。部署配置必须固定具体 DeepSeek 模型标识、上下文窗口、与该模型匹配且版本锁定的 tokenizer/计数规则；在每次请求发出前，Runtime 对即将发送的完整消息序列计数，以已确认 usage 和保守预估中的较大值计算剩余额度，并把本次最大输出限制在剩余输出和上下文窗口内。无法可靠计数、剩余额度不足或供应商 usage 超出预估时立即安全失败，不能把供应商单次 `max_tokens` 或 FastAPI 事后检查描述成跨调用硬上限。FastAPI 仍按已确认 usage 复核并累计；usage 丢失时本次运行费用标记为未知并终止，不继续扩大调用。模型或 tokenizer 变化属于运行时版本变更，必须重新评测后才能启用。
- 单个工具响应最多向模型提供 200 个有序聚合行和 256 KiB 规范化 JSON；整个模型上下文中的工具数据最多 512 KiB。
- 超出行数时返回 `truncated=true`、完整分组数量和实际返回覆盖；截断结果不能被描述为全量。
- 用户问题最多 2,000 个 Unicode 字符；结构化回答计划和最终渲染文本分别限制为 64 KiB。超限在触达模型或浏览器前拒绝。
- 每个用户最多每分钟接受 6 个创建请求；活动运行限制仍独立生效。管理员可以收紧该速率，但不能为普通用户绕开服务端上限。
- 所有限制均在 FastAPI 再次执行，不能相信模型、LangChain 或 Runtime 自报。

这些数值是约 20 人规模下的首版安全默认值，可以通过受控部署配置进一步收紧；任何放宽都必须更新评测基线并重新通过安全和容量验收。

## 8. 事实生成、模型输出与答案渲染

### 8.1 模型可做的事情

模型可以：

- 根据问题选择一个或多个允许工具。
- 从后端提供的关闭式 claims 中选择相关 `claim_id`。
- 安排结论、指标、限制说明和图表的展示顺序。

### 8.2 模型不能成为权威的内容

模型不能自行提供或改写：

- 数值、比例、货币、单位和日期。
- 排名、最高/最低、增长/下降等可计算结论。
- 数据覆盖状态和缺失日期。
- 数据集、发布版本、发布时间、站点配置版本。
- 站内链接、修订入口或权限判断。
- 因果结论。

上述内容全部由后端事实层计算。模型输出使用严格结构化 schema，只能提交本次运行已有 `claim_id` 的有序集合和受控展示组件枚举，不能提交面向用户的自然语言。后端验证 claim 属于当前快照、operands 完整、前置条件成立且引用齐全，再用版本化中文模板渲染全部可见句子。未知 claim、字段篡改、漏引、引用其他运行或不支持的因果问题都使校验失败；模型原文不会进入成功回答。

### 8.3 成功回答结构

成功回答由后端生成以下受控区块：

1. 简明结论。
2. 指标卡。
3. 必要的小型图表。
4. 后端模板生成的事实说明和限制说明。
5. 实际使用日期、覆盖/缺失状态和统计口径。
6. 精确版本引用。
7. 有权限用户可见的人工修正入口。

每个 claim 绑定一个 `reference_set_id`。引用集合中的每项至少包含报告日期、报表类型、`dataset_id`、`version_id`、`published_at` 和相关 `site_config_version_id`。引用 URL 由服务端生成，并指向现有版本或审核页面。最终答案只携带紧凑集合 ID 和摘要；完整引用通过分页接口读取，因此 366 天范围不会因为引用数量突破 64 KiB 回答上限。

模型内容按纯文本和受控组件渲染。原始 HTML、脚本、事件属性、`javascript:` URL 和任意 Markdown 链接都不能直接执行或导航。

## 9. 对话、运行与用量数据模型

以下为概念表；实施计划可在不改变不变量的前提下拆分命名和索引：

- `agent_conversations`：所有者、标题、创建时间、最后活动时间、固定 `expires_at`。
- `agent_messages`：所属对话、角色、受控内容、创建时间和固定 `expires_at`。
- `agent_runs`：所属对话与用户、站点、日期范围、状态、绝对截止时间、错误码、最终答案、创建与终态时间、固定 `expires_at`。
- `agent_run_contexts`：不可变快照清单、清单哈希、运行时/提示词/工具/校验器版本。
- `agent_model_calls`：调用 attempt、序号、请求前 `started_at`、供应商、供应商返回模型标识、状态、耗时、已确认 token usage、`confirmed / unknown / possible_charge` 费用状态和错误类别；不保存 API Key 或模型正文。
- `agent_tool_calls`：运行级全局调用序号、执行 attempt、工具名、规范化参数摘要、短期事实/claim 载荷、清单摘要、状态和截断元数据。
- `agent_reference_sets`：运行内去重的 coverage/contributor 引用集合、摘要和分页顺序；继承运行的内容到期时间。
- `agent_run_events`：每个运行单调递增的事件序号、受控事件类型、最小安全载荷和时间。
- `agent_conversation_active_runs`：每个对话最多一条活动运行指针。
- `agent_user_active_runs`：每个用户最多一条活动分析指针。
- `agent_runtime_slots`：全局模型并发槽和租约 fencing token。
- `agent_operation_tokens`：HTTP 幂等键、带密钥请求摘要及其 key version、用户和首次结果的不可变绑定；内容删除后保留无内容 tombstone。
- `agent_runtime_versions`：Runtime 实现、LangChain 版本、部署固定模型配置、提示词与工具 schema 哈希。
- `agent_runtime_current`：当前允许创建新运行的运行时版本指针。
- `agent_kill_switch`：单行持久开关、`hide_existing_answers`、原因代码、操作者和更新时间；默认关闭且不含内容。
- `agent_daily_usage`：按用户和日期聚合的调用次数、输入/输出 token、已知费用、未知费用次数、失败分类；不含问题、回答或工具内容。

### 9.1 状态与不变量

运行状态为：

```text
preparing → queued → running → validating → succeeded
     │          │         │          └──→ failed
     └──────────┴─────────┴──────────────→ failed
```

- 每个运行只能提交一个终态；终态后不得追加新的业务事件或覆盖答案。
- 同一对话最多一个活动运行，同一用户全系统最多一个活动分析。
- 全局真实模型并发首版为 2；这是未压测的保守初值，不是性能结论，必须可配置。
- 主 engine 先在一个事务中检查容量并创建不可领取的 `preparing` 占位、活动指针和 provider 槽；容量不足时不写入运行并返回 `429` 和 `Retry-After`。随后使用只读 engine 捕获完整快照，最后由主 engine 短事务把 `preparing` 原子转换为 `queued`。失败或超时会把占位终结并释放活动指针和槽；Runtime 永远不能领取 `preparing`，API 只有在 `queued` 成功后才返回 `202`。
- 模型调用、工具调用、事件和用量使用运行 ID、attempt、序号及 fencing token 去重。数据库中的最终答案、终态和已确认 usage 只能累计一次；供应商侧调用不承诺 exactly-once。

### 9.2 内容保留与备份

- 对话创建时确定统一 `expires_at = created_at + 30 天`；该对话的消息、运行、工具载荷、上下文和事件都继承同一到期时间，访问和追加运行不会续期。到期后用户新问题必须创建新对话。
- 未终结或仍持有有效租约的运行暂不清理；到期后最多给予 10 分钟终结宽限，之后强制标记失败、撤销租约并清理内容。
- 清理在事务边界内完成；并发读取只能看到完整资源或统一的 404，不能看到半份运行。
- 他人资源、已过期资源和不存在资源均返回 404，避免泄露资源存在性。
- 不含内容的每日用量聚合保留 12 个月。
- `agent_operation_tokens` 在内容删除后只保留用户 ID、操作类型、幂等 UUID、服务端秘密 HMAC-SHA-256 请求摘要、HMAC key version、首次 HTTP 状态和已删除结果标记，不保留裸 SHA-256、问题、答案、run ID 或可恢复业务内容；tombstone 保留 12 个月。在此期间同键重试返回 `410 idempotency_result_expired`，同键不同摘要仍返回 `409`。HMAC 密钥保存在数据库和备份之外的版本化 secret keyring；轮换时旧 key 至少保留到其最后一条 tombstone 过期，比较按记录的 key version 执行，删除仍在引用的 key 必须失败关闭。
- 对话和运行内容表不进入长期业务备份。每日用量、运行时版本和无内容幂等 tombstone 可纳入运维备份；恢复后聊天丢失是已接受结果，不得阻断业务数据恢复。
- 当前备份实现使用一次全库 `mysqldump`，因此阶段 11A 必须先升级备份 manifest/artifact 格式并改用版本控制的数据分类清单：数据库 schema 全量备份，业务数据按 allowlist 导出，明确排除 Agent 内容表；`information_schema` 中全部应用表与分类清单必须精确全等，迁移新增未分类表时备份失败关闭。分类校验、manifest 捕获和全部 schema/data 导出都在现有 maintenance write barrier 内完成，Agent 的所有主 engine 写连接也必须安装该 barrier。若实现为多个 dump，必须使用可证明共享同一 MySQL consistent snapshot 的机制；不能让 schema、allowlisted data 和 manifest 来自不同时间点。恢复器按显式格式版本处理新旧制品，未知格式失败关闭。
- 备份隐私验收在所有 Agent 内容表写入唯一 canary，解密并扫描每个 SQL artifact 时出现次数必须为 0；随后恢复到隔离库，验证 Agent 表结构存在且内容为空、allowlisted tombstone/用量按分类恢复、主业务恢复不依赖聊天记录。只检查恢复后为空不足以证明内容从未进入制品。
- DeepSeek API Key 永不进入数据库、备份或事件。提示词只持久化版本号和哈希，不保存包含秘密的运行时配置副本。

## 10. 公共 API 与 SSE 合同

### 10.1 接口

- `POST /api/agent/conversations`：创建对话、首个用户问题和运行，成功返回 `202`。
- `POST /api/agent/conversations/{conversation_id}/runs`：在已有对话中创建下一次运行，成功返回 `202`。
- `GET /api/agent/conversations`：列出当前用户未过期的对话摘要。
- `GET /api/agent/conversations/{conversation_id}`：返回当前用户的对话、消息和运行摘要。
- `GET /api/agent/runs/{run_id}`：返回权威运行快照、终态答案或规范化错误。
- `GET /api/agent/runs/{run_id}/events?after=N`：SSE 事件流，从序号 `N` 之后重放。
- `GET /api/agent/runs/{run_id}/references/{reference_set_id}?cursor=...`：仅所有者分页读取精确版本引用。
- `GET /api/agent/status`：返回功能开关、固定模型显示名、当前站点、可创建状态和非敏感限制。
- `GET /api/admin/agent/usage`：仅管理员读取无内容的按日用量、费用状态和规范错误聚合。
- `GET /internal/agent/health`：仅内部探针读取 Runtime 协议版本、就绪状态和不含秘密的供应商配置状态。

首版没有取消接口。浏览器离开或断线不取消后台运行。

### 10.2 请求保护

- 所有接口使用现有同源 Session。
- 两个写接口必须通过现有 CSRF 保护，并要求 UUID v4 `Idempotency-Key`。
- 幂等键在 12 个月 tombstone 保留期内绑定用户、操作类型和规范化请求摘要。内容尚未到期时，同键同请求返回首次运行；内容已删除时返回 `410`；同键不同请求始终返回 `409`。超过 12 个月后该键可以作为新操作使用。
- 创建请求包含用户问题和显式 `site_id`、`from_date`、`to_date`，后端在触达 Runtime 前重新授权站点并校验 366 天上限。
- `viewer`、`data_manager` 和 `admin` 都可以创建和查看自己的分析。
- 对话和运行只对所有者可见。管理员也不能读取他人的问题、回答或工具内容。

### 10.3 SSE 行为

- `GET run` 是权威快照，SSE 只用于降低等待感和断线恢复。
- 持久事件 ID 在单个运行内单调递增。`after=N` 或 `Last-Event-ID: N` 只返回 `N+1` 到当前末尾。
- 允许的事件包括 `queued`、`running`、`tool_started`、`tool_completed`、`validating`、`answer_ready` 和 `failed`；事件载荷不含提示词、模型原文或工具业务内容。
- SSE 投递语义是至少一次；页面按事件 ID 去重，因此多订阅、刷新和重连不会重复展示或重新调用模型。测试分别验证服务端持久序列无 gap、客户端最终展示每个事件一次，不能声称网络不可能重复字节。
- SSE 等待期间不持有数据库 Session、事务或连接；服务以短查询读取持久事件后释放连接，再等待通知或定时重新读取。
- Nginx 对该路由关闭响应缓冲并设置适合 90 秒运行及重连的超时。
- 在最终事实校验通过前，只流式展示真实进度。成功答案在 `answer_ready` 后作为受控区块一次性读取，不展示 DeepSeek 原始 token 流。

## 11. 内部 Runtime 协议与任务恢复

Runtime 通过窄化的 `/internal/agent/*` 接口完成：

- 领取一个任务和 fencing token。
- 对租约发送心跳。
- 请求执行一个白名单工具。
- 回传结构化回答计划、供应商 usage 或规范化失败。

本地开发使用受保护文件中的专用 worker token；生产固定使用双向 TLS 身份，不能复用用户 Session。生产拓扑使用独立的 internal listener 或专用 mTLS sidecar 终止双向 TLS，并使用专用 CA、短期 Runtime/FastAPI 证书和不中断轮换流程；`/internal/agent/*` 只在 `agent_control` 网络暴露，不经过面向用户的 edge Nginx，也不与公共明文 listener 共用可达入口。身份权限只允许上述四类动作，访问业务 API、草稿、发布和管理接口必须被拒绝。

任务租约短于运行绝对截止时间，并通过心跳续租。Worker 在领取后崩溃时，过期租约可以由另一 Worker 从持久化工具事实和状态机恢复；只有能够证明上一个供应商请求未发送，或其 usage 已确认且运行剩余 token/调用额度足够时，才允许创建新的执行 attempt。旧 fencing token 的心跳、工具请求和终态回传全部拒绝。工具调用上限和 token 额度按整个 run 跨 attempt 累计，不能因恢复重置。无论 ack 丢失、重复领取、乱序回传还是进程重启，数据库最终只能产生一份可见答案和一个终态。

外部 DeepSeek 调用无法保证 exactly-once。Runtime 在发请求前持久化 `started` attempt；只有收到并持久化供应商 usage 后才累计确认 token 和费用。如果请求可能已到达供应商、但 Runtime 在响应落库前崩溃，该 attempt 标记 `possible_charge`，token 和费用为 `unknown`，整个 run 立即安全失败。任何 attempt 一旦出现 `possible_charge` 或 unknown usage，该 run 后续供应商调用数必须为 0；恢复只允许终结状态、清理租约和记录用量，不能创建新执行 attempt。管理员用量页显示已确认费用和可能额外计费次数，不能把未知记为 0 或承诺账单精确一次。

对能够证明未发送，或已收到 usage 且供应商明确表明可安全重试的临时 DeepSeek 网络错误，最多重试 1 次，并同时服从剩余 token/调用额度和 90 秒绝对截止时间。结果不确定的断连默认安全失败并记录 `possible_charge`，绝不重试。认证失败、TLS 错误、无效结构、未知工具、策略违规和事实校验失败不重试。首版不静默切换其他模型。

## 12. 独立 `/agent` 页面

Agent 是系统内与数据审核、已发布看板和版本记录并列的独立页面，不是独立应用，也不是看板侧栏。

页面包含：

- 固定模型说明和“仅分析已发布数据”的边界提示。
- 显式日期范围选择器。
- 当前用户未过期的运行历史分组；同一分组中的每个问题仍是独立运行。
- 问题输入与运行状态。
- 结论、指标卡、小图、口径、覆盖情况和版本引用区。
- 旧回答过期提示与“使用当前发布数据重新分析”操作。
- 明确提示“本次不会读取上一问”；检测到“那个、继续、上一个”等未解析指代时，在调用模型前要求用户补充具体对象，而不是猜测旧上下文。

### 12.1 版本变化

回答始终展示生成时快照。若当前发布指针或站点配置已经变化，页面把旧回答标记为 `superseded`，但不改写其数字和引用。用户必须显式重新分析，系统不会在后台悄悄替换旧答案。

### 12.2 修正闭环

- `viewer`：只能查看允许的发布版本、复制引用、联系管理员或重新分析。
- `data_manager` / `admin`：如果引用仍是当前发布版本且没有活动草稿，显示“创建修订”；若已有活动草稿，显示“继续审核”；若引用已经过时，先引导查看当前发布版本，再决定创建或继续修订。
- 所有编辑仍在现有审核工作台完成。Agent 页面不能直接提交字段修改、备注、发布或回滚。
- 修改发布为新版本后，旧回答继续引用旧版本并标记已过时；返回 Agent 页面后由用户发起新运行。

## 13. 权限、隐私与网络隔离

### 13.1 对象与角色权限

- 所有角色只能访问自己的对话和运行内容。
- 管理员只能查看跨用户的每日调用量、已知/未知费用、状态、耗时和规范化错误类别，不能查看他人的问题、回答、工具载荷或模型原始响应。
- 版本引用目标继续执行现有角色权限；链接存在不能扩大 `viewer` 对草稿、内部备注或原始文件的访问。

### 13.2 发送给 DeepSeek 的数据

允许发送：

- 当前用户主动输入的问题。
- 冻结发布版本计算出的经营汇总。
- 已发布数据中的 SKU、ASIN、经过白名单规范化的退货原因/处置方式及满足最小分组阈值的聚合数量。
- 数据集/版本 ID、报告类型、日期、币种、时区和配置版本等不可识别单笔订单的口径元数据。

禁止发送：

- 草稿、原始 CSV、解析源值、失败批次和内部备注。
- 订单号、买家留言原文、物流牌照号和其他单笔记录标识。
- 密码、Session、CSRF、数据库 URL、文件路径、备份内容和任何密钥。

所有发往模型的字符串在序列化前统一经过版本化长度、字符集、控制字符、密钥和疑似 PII 检查，不能因为字段名是 SKU/ASIN 就跳过。ASIN 只允许严格核准格式；SKU 只允许受限长度和字符集，疑似含姓名、邮箱、电话、地址、订单号、长数字、密钥或自由文本时使用当前运行内稳定的非可逆别名或隐藏值，映射表不发送给模型。退货 `reason` 和 `detailed_disposition` 在源表中虽然是文本列，也不能原样发送；阶段 11A 必须引入版本化维度分类表，只将已知、核准值映射为受控枚举，未知或疑似敏感值统一映射为“其他/已隐藏”。SKU/ASIN/原因/处置组合只有聚合数量不少于 3 时才发送给模型；小于 3 的组只合并为“低频项”，具体 SKU/ASIN 不发送。阈值 3 是首版隐私默认值，不代表法律匿名化保证，供应商条款和 UI 必须说明云端模型仍会接收允许的发布聚合。若业务需要分析低频单项，必须另行设计和批准，不能由用户提示绕过。

发布字段和用户问题都作为不可信数据处理。字段中出现提示词注入、伪工具 JSON、HTML 或脚本，不能改变系统提示、工具白名单或服务端策略。

系统会拒绝明显包含密钥、密码、Session/CSRF token、数据库 URL 或个人联系方式模式的用户问题，并提示用户脱敏；但通用 DLP 不能证明识别所有用户主动粘贴的秘密。UI 必须明确警告不要输入个人信息、密钥或原始业务记录，安全承诺仅覆盖系统不会自动注入禁止字段。

### 13.3 容器与网络

- Agent Runtime 不注入任何 MySQL URL 或数据库账号。
- Runtime 具有镜像根文件系统和受保护 secret 文件，但不挂载 raw、backup、keyring、应用业务内容目录或 Docker socket。
- FastAPI 与 Runtime 共享独立 `agent_control` 内部网络；Runtime 不加入 MySQL 所在的 data 网络。生产使用第二个 `agent_egress` 网络连接强制出站代理。
- 主后端不持有 DeepSeek Key。Runtime 的所有外部流量必须经 deny-by-default 出站代理或等效主机防火墙，仅允许经过证书校验的已批准 DeepSeek API 主机和端口；DNS、直接 IP、内网网段、host gateway 和重定向绕过都必须被阻断。
- Docker bridge 只能分隔网络，不能独立实现域名级白名单。若目标服务器没有上述代理或等效防火墙，Agent 可以完成本地开发但不能通过生产上线门禁。
- DeepSeek Key 本地使用受保护文件，服务器使用 Docker Secret 或等效 secret store；不放入镜像、仓库、命令行、前端或普通环境转储。
- TLS 校验始终开启。
- LangChain tracing 默认并持续关闭，除非未来完成独立隐私设计与审批。

### 13.4 供应商合规门禁

在 DeepSeek 当前有效的数据保留、模型训练使用和数据地域条款由系统负责人确认并记录前，生产 `APP_AGENT_ENABLED` 必须保持 `false`。确认结果属于部署证据，不以本规格猜测供应商条款。

## 14. 费用、配置与运行保护

- 普通用户不能选择模型或参数。部署只允许一个经过批准的 DeepSeek 模型配置，并在每次运行记录供应商实际返回的模型标识。
- `APP_AGENT_ENABLED=false` 是进程启动的安全上限；数据库另有管理员控制的持久化 `agent_kill_switch`，默认关闭。只有环境上限和持久开关都启用时才可创建运行。FastAPI 在创建、领取、每次模型调用前、每次工具执行前和提交成功答案前读取或验证带版本的开关状态；Worker 心跳响应也携带当前状态。关闭后 5 秒内停止创建和领取，所有在途运行最迟在下一检查点或 10 秒恢复扫描上限内终结为 `agent_disabled`。已发出的供应商 HTTP 请求未必能撤回，其响应必须丢弃并按已确认 usage 或 `possible_charge` 记账，不能展示答案。终态回传只允许清理租约和用量，不能提交新业务内容。
- 模拟供应商只允许测试环境；生产检测到模拟配置、Runtime/mTLS/出站代理故障或 DeepSeek 不可达时，Agent Runtime 不就绪且 `/api/agent/status` 返回禁用原因，但公共 FastAPI 仍可启动，现有 `/api/health/ready` 不依赖 Runtime 或 DeepSeek，主平台继续就绪。只有主平台自身依赖失败才使公共 readiness 失败。
- 首版每用户最多 1 个活动分析，全局最多 2 个真实模型调用；未压测前不能把该设置描述为容量结论。
- 供应商返回且成功持久化 token usage 时按已确认值累计。费用使用带生效时间的价格配置计算，并记录价格版本。
- 缺少 token 或价格时费用状态为 `unknown`，不能记为 0、估算或编造。
- 管理员可以看到按日聚合的已知费用、未知费用次数、`possible_charge` 次数、失败分类和告警状态。
- 日/月费用只统计并按可配置阈值告警，不因超过金额自动拒绝用户请求。认证失败、系统容量、安全策略和功能开关仍可以拒绝请求。
- 问题、回答和工具内容不写入应用、Nginx、容器或审计日志。结构化日志只记录 run ID、用户 ID、状态、安全错误码、时长和不含内容的计数。

## 15. 错误处理

错误对用户使用稳定、可操作的类别，不透传供应商原始错误：

- `agent_disabled`
- `capacity_unavailable`
- `provider_authentication_failed`
- `provider_rate_limited`
- `provider_unavailable`
- `provider_timeout`
- `invalid_model_response`
- `tool_policy_violation`
- `data_snapshot_unavailable`
- `fact_validation_failed`
- `run_deadline_exceeded`

DeepSeek 的 401、429、5xx、断网、TLS 错、超时、无效 JSON、未知工具、循环工具调用、超长输出和缺失 usage 都必须映射到规范状态。原始错误即使回显用户问题或密钥片段，也不能写入数据库事件、日志或浏览器。

90 秒截止后不展示部分答案。工具或模型已经完成但终态提交发生竞态时，数据库 fencing 和终态唯一约束决定唯一结果；旧 Worker 不能覆盖新 Worker 或已失败的终态。所有配额和活动指针在终态事务或恢复任务中释放。

## 16. 测试与评测

### 16.1 确定性事实 oracle

建立一个小型、不可变、完全合成的已发布数据集，由人工核准，并使用独立参考计算器或手写 golden 生成期望事实。参考实现不能复用生产 `agent_tools`、生产聚合查询或模型输出。

逐字段验证：

- Decimal 金额、整数、比例、空值、单位和币种。
- 报告日、事件日、时区和站点配置版本。
- 0 与缺失、部分覆盖、零分母、负修订。
- top-N、并列、相同 SKU/ASIN、未知字段值。
- 当前站点/币种边界，以及伪造其他 `site_id` 的拒绝。
- 报告日在事件范围外、但事件日在范围内的退货版本仍被捕获。
- 多个候选版本中仅部分命中时，coverage references 包含全部候选，matching references 只包含命中版本，每个 fact 的 contributor references 只包含实际参与该 fact 的 matching 版本。
- 存在当前已发布退货版本、但事件日范围内没有任何活动行时，coverage references 仍与全部候选版本精确相等，matching 和 contributor references 均为空，结果为已完整扫描后的 0/无命中而非缺失，并强制显示数据水位提示。
- oracle 从发布指针独立构造事件日候选全集；测试故意让生产读取器漏扫一个零命中候选版本时，coverage 全等校验必须失败，不能由查询结果自证完整。
- 夏令时折叠、跳跃和本地午夜边界先经过安全 UTC envelope，再按冻结 IANA 时区精确复核本地日期；边界行不能重复或漏计。
- 事件日工具截断时，matching 可以大于已展示 facts 的 contributor 并集，但必须返回确定性的完整分组数、`truncated=true` 和强制覆盖提示。
- 报告日期期望网格中的 `no_data / unavailable / partial_data / published-zero`。
- 每个工具的 projected coverage references 与 expected refs 全等，fact contributor references 是精确可复算子集。

模型原始结构化输出不做整段字符串比较。评测断言最终 facts、claims、引用、状态机和安全失败；面向用户的模板文案则可按模板版本做确定性测试。

### 16.2 每次提交的离线测试

使用脚本化 fake provider 和 fake clock，禁止联网，覆盖：

- 三工具精确白名单、关闭式 schema、额外参数和未知工具。
- 日期 1/366/367 天，商品 limit 1/200/0/201。
- 并行、重复和非法调用仍计入 6 次总额度。
- 7 次模型调用、输入/输出 token、每分钟创建速率和 90 秒绝对截止时间，不使用真实 sleep。
- 模型篡改数字、漏引、错引、伪造实体、版本或链接时全部拒绝。
- DeepSeek 429/5xx/超时/断连、malformed JSON、循环调用和无 usage。
- 默认安装 socket/HTTP transport guard，除显式标记的真实供应商测试外任何外联尝试立即失败；普通测试不能因开发机网络可用而意外调用 DeepSeek。
- Session、CSRF、幂等、所有者隔离、同对话单运行和同用户单运行。
- 并发同键同请求只创建一个运行；同键不同请求返回 409；内容删除后的 410 和 12 个月 tombstone 过期语义明确。
- SSE 分片、去重、重放、断线、多订阅和终态。
- Worker lease、fencing、ack 丢失、进程重启和重复终态。
- 在供应商请求发出后、usage 持久化前注入进程崩溃时，attempt 标记 `possible_charge / unknown`，run 安全失败，恢复后的供应商调用数精确为 0，只完成终态与用量清理。
- 30 天、10 分钟终结宽限和 12 个月 tombstone/用量清理边界，清理时不出现半份资源。
- 模型文本、HTML、脚本和危险链接只能作为安全文本处理。
- 上一轮问题、答案和 fact/claim 从不进入下一轮模型请求；未解析指代在调用前被拒绝。

### 16.3 MySQL 隔离集成测试

MySQL 测试只允许 `clsen_data_test*` 隔离库，并使用 `--require-mysql` 防止测试被静默跳过。覆盖：

- 专用连接按顺序设置 `REPEATABLE READ` 并执行 `START TRANSACTION WITH CONSISTENT SNAPSHOT`；第一次一致性读前没有其他读取，捕获阶段不使用 locking read；同一快照原子捕获报告日网格、全部事件日候选 publication 和 config manifest，且 `preparing` 到 `queued` 失败窗口不产生可领取任务。
- 在快照后、首个工具后和工具之间通过 barrier 发布 V2、回滚或切换时区；旧运行始终只用 V1，新运行才用 V2。
- 冻结后发布、回滚或切换配置不能改变旧运行的 candidate、matching、coverage、contributor 或配置字段；新运行才捕获变化。数据库拒绝普通账号就地修改/删除已被引用的 `site_config_versions`。
- 草稿、历史版本、失败批次、原始内容和内部备注不影响 Agent 结果。
- Runtime 不获得数据库账号；独立 `agent_reader` 只被授予安全视图的 SELECT，基础表读取和所有业务写 SQL 被数据库权限拒绝。
- 恶意问题运行前后，业务表、发布指针和审计记录没有变化。
- 双 Worker 竞争、20 个账号同时提交和多个 API/Worker 副本下，仍满足每用户 1、全局 2 的不变量。
- 使用固定随机种子连续执行 50 轮关键并发竞态，不出现 flaky、重复数据库终态、配额泄漏或持久事件缺口。供应商结果不确定窗口必须落入 `possible_charge`，不能断言供应商侧 exactly-once。该数字是计划验收门槛，不是现有测试结果。

### 16.4 泄漏与注入测试

在草稿、历史版本、失败批次、原始文件、订单号、内部备注、环境密钥和模拟 provider 错误中放入唯一 canary。另在允许发送给模型的合成问题和聚合字段中放入日志专用 canary。捕获模型 HTTP 请求，并扫描 API/SSE、DOM、应用日志、Nginx 日志和容器日志；禁止发送字段和密钥不能进入模型请求，所有内容 canary 都不能进入日志。

在用户问题及已发布 SKU、ASIN、原因字段中注入 `ignore instructions`、伪工具 JSON、SQL、文件、联网、写入请求和 XSS。断言它们不能突破三个工具、不能改变范围或版本、不能调用业务写服务，也不能在浏览器执行。另覆盖维度白名单、疑似 PII 映射、低于 3 的小组聚合以及常见密钥/联系方式输入拒绝；测试不能把这些规则宣称为完备匿名化或能识别用户主动粘贴的全部秘密。

### 16.5 前端与部署测试

- Vitest 覆盖 `/agent` 路由、日期范围、queued/running/validating/succeeded/failed/429/禁用/费用未知状态，以及三个角色的修正入口。
- Playwright fixture E2E 覆盖提问、进度、断线重连、答案、图表、版本引用、跳转审核和返回重新分析；这类测试使用模拟 API，不能声称是后端全栈 E2E。
- 受保护的容器 smoke 使用真实 FastAPI、隔离 MySQL 和 stub Runtime。
- 部署合同验证 Runtime 无数据库配置与敏感卷、不在 data 网络、生产独立 mTLS internal listener/sidecar、专用 CA 与证书轮换、`/internal/agent/*` 不经 edge、tracing 关闭、SSE 不缓冲且不占用长事务、日志无内容。
- 从 Runtime 容器内实际验证：允许经代理访问批准的 DeepSeek 主机，拒绝其他域名、直接 IP、内网、host gateway 和重定向目标。
- 现有 MySQL 8.0/8.4 CI、测试矩阵和部署验证显式加入 Agent 测试文件，不依赖自动发现猜测。
- 现有部署验证增加 Agent 状态/健康与公共 readiness 解耦、独立 reader 权限、持久 kill switch、活动运行终结和恢复开启演练；Runtime、mTLS、代理和 DeepSeek 分别故障时主平台仍保持 ready。

### 16.6 DeepSeek 真实冒烟与人工评测

真实 DeepSeek 测试固定注册 `deepseek_live` pytest marker，并同时要求显式 CLI 开关；缺少任一条件都不执行。普通 CI、本地测试和 MySQL matrix 的命令必须明确排除 `mysql` 与 `deepseek_live` 中不适用的集合，不能依赖文件名或自动发现。live job 只在目标环境从专用 secret store 读取独立低权限 API Key，不读取仓库 `.env`，只使用合成或单独获批的非敏感已发布聚合数据且不连接正式数据库。固定检查最多重试 2 次，全部尝试服从预先锁定的安全额度。它验证：

- 固定模型可连接且 TLS 正常。
- 使用三个定向合成问题分别观察到对应工具至少一次成功调用；某次未选择预期工具可在固定重试内重试，仍未观察到则保持禁用，而不是伪造工具调用成功。
- 至少一个多工具问题在固定重试内完成受控循环。
- tool binding、结构化回答、调用上限、超时和 SSE 端到端合同成立。

真实模型输出不作为 deterministic golden，也不进入普通 PR 必过测试。更大的模型评测集必须版本化问题、fixture、prompt、工具 schema、模型标识、参数和重复次数，并报告原始分母与安全失败分类，不能用一个平均“准确率”掩盖高风险题目。

模型不生成最终自由文案；业务评审评价其 claim 选择的相关性、完整性和服务端模板可读性，由至少两人按固定 rubric 盲评并仲裁分歧。LLM-as-judge 只能辅助。可用性通过率由产品/数据负责人在线上评测开始前书面确定，不能看完结果后调整。无论该阈值如何，任何展示的错数、错版本、漏引、越权或泄漏均为零容忍。

## 17. 上线验收门禁

生产功能开关只有在以下条件全部满足后才能开启：

1. 所有确定性单元、合同、MySQL 集成、安全和前端测试通过。
2. 合成 oracle 中展示事实、日期、单位、覆盖和引用逐字段完全一致。
3. 快照并发切换场景没有任何跨版本混用。
4. 草稿、秘密、原始内容和内部字段 canary 泄漏为 0。
5. 越权、业务写、任意 SQL、敏感文件访问和绕过代理的非 DeepSeek 出站能力为 0。
6. 持久 SSE 序列无 gap，客户端去重后无重复展示；幂等与 Worker 恢复无重复用户可见答案或数据库终态，所有供应商不确定调用均标记 `possible_charge`。
7. 目标服务器使用正式镜像、真实 Secret 和真实网络边界完成 DeepSeek 合成数据冒烟。
8. Runtime 无 MySQL/原始文件权限，并实际验证业务写请求被拒绝。
9. DeepSeek 数据保留、训练和地域条款已由负责人确认。
10. 持久 kill switch 关闭、活动运行安全终结、重新开启和镜像回滚演练成功。
11. 在同一目标环境先记录 Agent 关闭时的现有 20-viewer + 1-publish 基线，再在 Agent 全局 2 并发和相同业务负载下重复；发布必须成功、所有看板响应必须正确且无 5xx/连接池超时，业务请求 p95 不得比基线增加超过 25% 或超过 2 秒（取更严格者）。新增独立目标环境性能脚本，固定镜像与数据 fixture、预热 2 分钟、每个场景测量 10 分钟、20 个 viewer 各自持续执行同一请求组合并同时执行可重复的发布操作；按单请求类型分别从全部非预热样本计算 p95，保存带时间戳的原始延迟样本、错误计数、环境和镜像 digest。基线与 Agent 场景在同一次验收窗口各运行至少 3 轮，使用各轮 p95 的中位数比较。现有只验证正确性的 20-viewer 部署测试不能充当这项性能证据。这些是上线验收阈值，不是当前性能结果。

若上述任何门禁失败，主平台可继续运行，但 Agent 保持禁用。

## 18. 上线策略与维护

### 18.1 分阶段启用

1. 默认禁用并完成迁移、离线和隔离测试。
2. 在隔离环境使用 stub provider 完成全栈验证。
3. 在目标服务器用合成数据完成 DeepSeek 冒烟。
4. 先仅向管理员和数据管理员开放短期观察。
5. 确认没有静默错数、泄漏、越权和资源争用后，再向全部登录用户开放。

阶段性开放由服务端角色 allowlist 控制，并记录启用范围；不使用前端隐藏模拟权限。该临时 allowlist 只用于上线观察，最终正式开启前必须纳入 viewer 权限 E2E，之后 `viewer` 拥有相同的只读分析能力。

### 18.2 监控

仅收集无内容指标：

- p50/p95 运行时长和 90 秒超时数量。
- 429、provider 错误、validator 拒绝和安全失败率。
- token、已知费用、未知费用、`possible_charge` 次数和告警。
- 旧回答过期率、清理任务状态和容量公平性。
- Agent 开启期间主看板、审核、发布的连接池等待和错误。

这些指标用于运维和调参，不替代准确性门禁。管理员看不到问题和回答内容。

### 18.3 立即停用条件

出现以下任一情况立即关闭持久 `agent_kill_switch`；必要时再把 `APP_AGENT_ENABLED=false` 并重启，主平台继续运行：

- 静默错数、错版本、漏引或快照混用。
- 未授权数据、密钥或对话内容泄漏。
- Agent 触发业务写入或突破对象权限。
- Runtime 获得不应有的数据库、文件或网络访问。
- Agent 明显影响审核、发布或已发布看板可用性。

停用后默认仍允许用户查看尚未过期的既有成功回答，但不能创建新运行。持久开关包含独立 `hide_existing_answers` 标志；若停用原因涉及答案可信度或泄漏，管理员同时启用该标志并按事件响应流程处理。开关本身只保存状态、原因代码、操作者和时间，不记录问题或答案。

### 18.4 发布证据包

每次生产启用或模型/提示词/工具 schema 变更保留不含业务内容的证据：

- 合成 fixture/eval SHA。
- prompt、工具 schema、校验器和运行时版本。
- 供应商返回模型标识和镜像 digest。
- 环境、时间、逐题原始计数和人工仲裁结论。
- canary 扫描、并发/故障注入和部署隔离报告。

证据只使用合成数据。生产问题、回答和工具载荷不进入测试产物。

## 19. 风险与明确取舍

### 19.1 模型仍可能不可用

确定性校验可以阻止错误事实展示，但不能保证模型每次都产生可接受结构。安全失败会降低可用性，这是为了数据准确性采取的明确取舍。

### 19.2 供应商接收用户问题和发布聚合

云端模型必然接收用户输入和允许的聚合数据。生产开启前必须完成条款确认和用户界面提示；若未来不能接受该数据边界，应切换受控本地模型，而不是弱化告知。

### 19.3 出站白名单需要基础设施支持

Compose 网络隔离不能证明域名级白名单。没有 deny-by-default 代理或等效主机防火墙时，只能进行本地开发，不能启用生产 Agent。代理配置错误会直接降低可用性，但这是防止 Runtime 任意出站的明确取舍。

### 19.4 短期对话不是业务记录

聊天 30 天后删除且不进入长期业务备份。业务修正的权威记录始终是现有草稿、修改事件、备注、校验和发布历史，不能依赖 Agent 对话保存决策。

### 19.5 首版并发值未经压测

每用户 1、全局 2 是保守安全初值，不是性能承诺。必须通过目标服务器验证再调整；放宽不能绕过全局容量、数据库隔离和主业务优先级。

### 19.6 供应商费用可能未知

DeepSeek 没有在本规格中提供可验证的请求幂等或即时账单对账合同。Runtime 在供应商已收到请求、但本地未收到 usage 时，系统只能记录 `possible_charge`，不能精确给出本次实际费用。管理员需要以供应商账单作最终对账，产品页面不能把本地已确认费用描述为账单总额。

### 19.7 小组阈值不是匿名化证明

规范化维度和最小组数 3 会减少偶然披露，但不能构成法律意义的匿名化保证。生产开启仍取决于供应商条款、业务数据分类和负责人批准；禁止字段或疑似 PII 会被隐藏而牺牲分析粒度。

## 20. 完成定义

阶段 11A 只有在以下事项全部完成后才算交付：

- 独立 `/agent` 页面和个人短期运行历史可用，每次问题不复用旧模型上下文。
- LangChain DeepSeek Runtime 通过内部协议工作，Runtime 不持有数据库权限。
- 三个只读工具使用冻结快照，不会跨版本漂移。
- 所有展示 facts、claims、模板文案和引用经过服务端确定性生成与校验。
- 三类角色的查看与人工修正闭环符合本规格。
- 留存、备份排除、日志脱敏、费用统计和功能开关可验证。
- 离线、MySQL、前端、部署、安全和目标环境冒烟满足第 17 节门禁。
- 用户文档、部署文档、故障关闭和恢复步骤已经更新。

完成阶段 11A 不等于启用生产功能。若供应商条款、服务器网络边界或目标环境验收尚未完成，代码可以交付，但生产 Agent 必须继续保持禁用。
