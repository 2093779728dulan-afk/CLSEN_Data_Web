# 总表首页与审核流程优化设计

## 目标

把应用首页从“直接进入单日审核”调整为当前月份的发布数据总表，让用户先看到全局状态，再进入具体日期处理。同时增加按商品款号聚合的总表和弹出式商品信息卡，并修复批量导入恢复、原文件探测和大文件预览中的一致性与性能问题。

本设计保持系统的核心边界：所有经营指标和产品指标只读取当前发布版本；草稿、失败导入和历史版本不会进入发布数据结果。

## 用户与主要任务

- 管理员和数据管理员：从每日总表定位缺失、审核中或部分发布的日期，点击后进入独立审核页。
- 查看人员：浏览相同的每日总表和产品总表，点击日期后进入单日只读发布详情。
- 所有角色：按月份浏览已发布商品表现，点击商品款号行后在当前页面查看一张商品信息卡。

## 信息架构

### 路由

- `/`：发布数据首页，默认打开“每日总表”。
- `/review/:reportDate`：独立日期审核页，仅管理员和数据管理员可写。
- `/published/:reportDate`：单日只读发布详情，供查看人员使用，也可供可写角色追溯。
- 现有版本记录、管理控制台等路由保持不变。

商品不增加独立详情路由。产品总表行点击后打开页面内的模态信息卡；关闭卡片后保留月份、标签、搜索、排序和分页状态。

### 首页结构

1. 紧凑页面标题、当前站点和月份选择。
2. 搜索、状态筛选，以及可写角色可见的“进入今日审核”主操作。
3. “每日总表 / 产品总表”两个同级标签。
4. 高密度表格主体和服务端分页。

首页不使用大面积欢迎区、指标卡片阵列、装饰性渐变或内嵌审核表单。页面的主要视觉对象就是总表。

## 每日总表

### 数据粒度

当前月份每天一行，默认按日期倒序。行包含：

- 报告日；
- 经营报告状态；
- 退货报告状态；
- 销售额；
- 订购数；
- 会话数；
- 转化率；
- 退货数；
- 阻断或待办摘要；
- 行操作。

未发布报告的业务值显示为破折号，不以零代替。日期状态分为：两类均发布、部分发布、审核中、失败或阻断、完全无数据、未来日期。只有已经发生且存在一类报告或审核活动的日期，才计入“仍需补齐”；未来日期和完全无数据日期不计入该数字。

### 行点击

- 管理员、数据管理员：进入 `/review/:reportDate`。
- 查看人员：进入 `/published/:reportDate`。

单元格内若存在独立按钮，其点击不触发行级导航。

## 产品总表

### 商品、变体与标识层级

产品总表的一行表示一个商品款号，而不是一个 SKU 或 ASIN。Seller SKU 始终遵循 `款号-颜色-尺寸` 三段格式，例如：

- `2301-White-S`；
- `2301-White-M`；
- `2301-Black-S`。

这三个 Seller SKU 都归入商品款号 `2301`。领域层级为：

1. 商品：由数字款号 `style_code` 稳定标识，例如 `2301`；
2. 变体：由完整 Seller SKU 标识，并包含独立的颜色和尺寸；
3. 外部标识：一个变体可以关联一个或多个 ASIN、FNSKU。

后端使用同一个严格解析规则处理经营和退货数据：

```text
^(?<style_code>[0-9]+)-(?<color>[^-]+)-(?<size>[^-]+)$
```

不符合规则的历史或异常 SKU 不参与正常商品合并，而进入明确标注的“未归类 SKU”，等待数据管理员处理。第一版不新增需要人工维护的商品主档；商品关系从当前发布数据中的 Seller SKU 及其 ASIN/FNSKU 关联得出。

### 列与交互

产品总表按商品款号聚合当前所选月份的当前发布版本，包含：

- 商品款号；
- 商品名称；
- 变体数量；
- 颜色数量；
- 尺寸数量；
- 销售额；
- 订购数；
- 会话数；
- 转化率；
- 退货数；
- 有发布数据的天数；
- 最近发布日。

默认按销售额倒序，支持款号、Seller SKU、ASIN、FNSKU 和商品名称搜索，以及列排序和服务端分页。搜索、排序、月份、标签和页码写入 URL，以便返回和刷新后恢复现场。

### 商品信息卡

点击商品款号行打开居中的模态信息卡，不离开首页。卡片是一张完整的信息载体，不再嵌套额外页面或完整明细表。

卡片包含：

- 商品款号；
- 商品名称；
- 关联的全部变体，逐项展示 Seller SKU、颜色、尺寸、ASIN 和 FNSKU；
- 当前月份销售额、订购数、会话数、转化率、退货数和有数据天数；
- 最近发布日；
- 一个紧凑的每日趋势图。

商品名称优先使用该款号最新已发布数据中的标题或 `product_name`。如果不同变体名称不一致，卡片顶部以款号为主标题，名称区域标记“存在多个变体名称”，并在变体列表中保留每个变体的原始名称。品牌、分类和图片只有在存在权威数据源时才显示；没有权威值时明确显示“未维护”，不得生成占位业务信息或从非发布数据推断。

卡片必须支持关闭按钮、`Escape` 关闭、焦点锁定和关闭后的焦点恢复。手机端卡片占据可用视口并内部滚动。

## 后端只读查询

新增或扩展三个只读查询契约：

### Daily ledger

返回日期范围内的报告状态、当前发布指标和不泄露草稿内容的待处理摘要。指标查询与状态查询在同一请求快照中组合，避免浏览器拼接多个时间点的数据。

### Product ledger

使用统一 Seller SKU 解析器提取 `style_code`、颜色和尺寸，再按 `style_code` 聚合当前发布的经营和退货数据。查询接受日期范围、款号/SKU/ASIN/FNSKU/名称搜索、排序、页码和页大小。响应包含总行数与稳定排序键。

### Product card

按 `style_code` 和日期范围返回商品名称状态、变体及外部标识列表、月度汇总、每日紧凑趋势以及最近发布日。只读取当前发布指针。`style_code` 作为独立的数字字符串参数传递，不以 ASIN、FNSKU 或完整 SKU 代替商品身份。

所有新接口对查看人员开放读取，并继续执行站点边界和字段脱敏规则。

## 审核流程稳定性优化

### 单一状态源

将 `ImportReviewFlow` 的顶层上传、识别、解析状态与队列项副本合并为 reducer/显式状态机。活动队列项是上传批次状态的唯一来源；切换文件、重新识别、重新解析和发布都通过 reducer 事件更新。

主要阶段为：

- intake；
- inspection；
- parsed；
- draft；
- published；
- failed。

状态机不替代服务端事实。恢复后仍需要以服务端批次、草稿和发布指针校验本地快照。

### 恢复与退出

- 会话存储键绑定会话架构版本、站点 ID、用户 ID 和报告日。
- 成功退出或服务端确认会话失效时，清理当前用户的审核恢复键。
- JSON 恢复数据进行完整结构校验；损坏或旧版本数据安全丢弃。
- 批次有效性只在首次恢复和批次 ID 集合变化时检查，不因日期、编码或解析状态修改而重复检查所有批次。

### 原文件 HEAD

HEAD 请求复用 GET 的批次关联、原文件元数据和完整性状态判断，但不读取文件内容。数据库批次不存在返回 404；完整性状态不可用返回与 GET 一致的 409。

### 大文件预览

浏览器不再下载并同步解析完整原始 CSV。后端提供受限预览，按确认编码流式读取，最多返回表头和前 200 个数据行，并返回是否截断。界面明确显示“预览前 200 行”，完整原文件继续通过下载获取。

第一版预览不提供全文件搜索或任意页跳转，避免每次请求重新扫描最高 100MB 文件。搜索只作用于已经返回的预览行。

## 视觉与响应式契约

- 延续现有米白、深绿、细边框和证据台账语言。
- 表头和首列在桌面端固定。
- 状态使用文字加色点，不能只依赖颜色。
- 行悬停只表达可点击性，不使用装饰性动画。
- 桌面端保持高密度表格；不把业务字段拆成卡片矩阵。
- 手机端每日表改为紧凑分组列表；产品表保留商品款号、商品名称、销售额、订购数和退货数，其余内容进入商品信息卡。

## 状态与错误处理

- 加载：保留表头，显示行级骨架。
- 空月份：说明没有已发布数据；可写角色获得进入审核的明确入口。
- 部分发布：经营和退货分别显示状态，缺失指标显示破折号。
- 查询错误：保留当前筛选，提供原位重试。
- 权限不足：不显示写操作，路由服务端仍执行角色校验。
- 信息卡加载错误：卡片保留商品款号与重试按钮，不清空首页表格。

## 测试策略

### 后端

- 每日状态与当前发布指标组合正确。
- Seller SKU 三段解析、商品款号聚合、变体及 ASIN/FNSKU 关联正确。
- 不符合规则的 SKU 进入“未归类 SKU”，不会错误合并到正常商品。
- 商品查询分页、多标识搜索和稳定排序正确。
- 草稿和历史版本不进入任何首页或产品卡结果。
- HEAD 与 GET 的存在性、权限和完整性状态一致。
- 预览行数、编码、截断标志和大文件边界正确。

### 前端

- 首页默认每日总表，URL 可恢复标签、月份、筛选、排序和页码。
- 不同角色点击日期后的路由正确。
- 商品款号行打开信息卡，变体列表完整，键盘关闭和焦点恢复正确。
- 未来日期、完全无数据、部分发布和阻断状态表达正确。
- 队列切换和重新解析不会恢复旧识别状态。
- 退出后不恢复上一账号的本地队列。
- 桌面和手机关键断点下，主要操作与数据仍可访问。

## 非目标

- 不创建独立商品详情页。
- 不在第一版维护商品主档、上传商品图片或编辑品牌/分类。
- 不在首页直接编辑草稿。
- 不让商品成为动态横向列；商品款号始终作为产品总表的行。
- 不为原始 CSV 实现全文件浏览器搜索。

## P0 替代关系（2026-08-20）

本设计中的 `style_code`、严格三段 Seller SKU 解析、产品总表和商品信息卡是 `identity_source=legacy_parser` 的兼容体验，不是权威商品身份。`style_code` 只允许作为旧 API path、旧页面分组键和来源建议展示；它不能创建或替代 `style_id/sku_id/style_revision_id/sku_revision_id`，也不能作为 P0 映射、生产或库存外键。

P0 新 `/products` 与 `/products/{style_id}` 只使用已批准商品目录，单个请求不得在 404、空结果、数字字符串或未初始化目录时回退 legacy parser。正式入口切换前新旧 API 双轨保留；切换只接受 release/build 级 `legacy_parser|p0_catalog` 闭集，整套 UI/adapter 同时切换或回滚。旧 ledger body 保持兼容并用 header 明确 `legacy_parser`，不得混入 P0 version。
