# 总表首页 UI 设计契约

## 页面任务

让管理员、数据管理员和查看人员在进入系统后，立即看清当前月份每天的发布完整度与经营结果，并能从一行进入对应日期；产品视图用于按款号查找商品，再通过一张信息卡核对全部变体和月度表现。

## 信息层级

1. 当前站点、月份和唯一主操作“进入今日审核”；
2. “每日总表 / 产品总表”同级标签和紧凑筛选；
3. 高密度表格，状态、缺口和经营值在同一行完成判断；
4. 日期进入独立页面，产品在原页面打开一张模态信息卡。

## 视觉语言

- 延续项目的米白纸面、深绿文字和主操作、白色表面、灰绿细边框；
- 表格和模态依靠 1px 边框与表面色差建立层级，不使用投影；
- 状态必须同时使用中文文字和小色点，颜色只做辅助；
- 小号大写标签只用于表头、款号和证据字段，不替代清晰中文名称；
- 主操作颜色只用于真正可执行的审核入口，筛选和分页保持中性。

## 工作流与组件

- 允许：月选择、状态筛选、搜索、同级标签、可排序表头、分页、行级导航、单张商品信息卡、行骨架、原位错误重试；
- 首页不允许直接编辑草稿，也不展示上传、解析或发布控件；
- 商品信息卡必须包含关闭、Escape、焦点锁定和关闭后焦点恢复；
- 所有可见控件必须有真实结果，异常 SKU 行不伪装成可打开的商品。

## 必需状态

- 加载：保留表头和列宽，显示行骨架；
- 空月：明确“本月没有已发布数据”，可写角色显示进入审核入口；
- 部分发布：经营与退货状态分开，缺失业务值显示 `—`；
- 错误：保留 URL 筛选并原位重试；
- 权限：viewer 不显示写操作，独立审核路由仍做角色保护；
- 商品卡错误：保留款号和重试，不清空底层产品表。

## 响应式规则

- 桌面：固定表头和首列，保持高密度表格；
- 中等宽度：工具栏换行，表格允许受控横向滚动；
- 手机：每日表转为紧凑分组列表；产品表仅保留款号、名称、销售额、订购数和退货数；商品卡占满可用视口并内部滚动。

## 明确拒绝

- 欢迎 hero、通用 dashboard 卡片阵列、bento 布局；
- 假指标、活动流、占位品牌/分类/图片；
- 装饰性渐变、玻璃、发光、漂浮阴影和无业务意义动画；
- “概览”“洞察”“了解更多”等无法说明业务结果的泛化文案；
- 把桌面表格简单压缩到手机，或把每个单元格拆成卡片墙。

## 参考决策

- UIZZE Ramp：采用暖色纸面、单一主操作色、细边框替代阴影和左对齐数据层级；
- UIZZE PostHog：参考分析产品以筛选和数据结果为主、状态就地反馈的工作流；
- UIZZE GitHub：参考紧凑工具栏、可扫描表格/列表和克制的行级操作。
