# 全站蓝白数据运营视觉系统设计

日期：2026-08-14

## 1. 目标

把现有页面统一成专业、克制、高密度的蓝白数据运营工作台。统一颜色、排版、
页面外壳、表格、表单、弹窗和状态反馈，但不借视觉改造改变管理员、版本记录、
导入审核等页面的业务流程或权限边界。

日期工作台结构增强和跨日期发布明细总表使用本视觉系统，并作为数据表组件的
首批落地页面。

本设计取代 `2026-08-14-ledger-home-ui-contract.md` 与
`2026-08-14-ledger-home-and-workflow-optimization-design.md` 中“米白、深绿”视觉
语言的部分；两份既有文档中的路由、权限、数据口径、恢复流程和业务交互契约继续
有效，除非本设计明确涉及视觉层级或响应式呈现。实施计划必须按这一优先级解读，
不得同时保留两套主题。

## 2. 设计原则

- 数据和当前任务始终是页面第一视觉层；
- 一页只突出一个主要操作；
- 蓝色表达导航、选择和主操作，不作为装饰；
- 绿色、黄色、红色只表达真实业务状态；
- 白色画布与浅蓝灰层级替代大面积深色和过量阴影；
- 桌面端优先高密度，移动端保留查看和必要操作；
- 不使用渐变、玻璃、发光、装饰性指标卡或宣传式 Hero。

## 3. 设计令牌

所有页面通过 CSS 自定义属性使用语义令牌，禁止页面组件自行发明近似颜色。

### 3.1 颜色

| 令牌 | 建议值 | 用途 |
| --- | --- | --- |
| `--color-page` | `#F5F8FB` | 页面背景 |
| `--color-surface` | `#FFFFFF` | 表格、表单、弹窗 |
| `--color-surface-muted` | `#EDF4FA` | 表头、冻结列、次级区 |
| `--color-primary` | `#1769AA` | 主操作、选中导航 |
| `--color-primary-strong` | `#0D4F86` | 悬停、重要标题 |
| `--color-text` | `#17324D` | 正文 |
| `--color-text-muted` | `#60788D` | 辅助文字 |
| `--color-border` | `#C7D6E2` | 普通边框 |
| `--color-border-subtle` | `#DFE8EF` | 表格内部边线 |
| `--color-success` | `#287A55` | 成功 |
| `--color-warning` | `#946B16` | 警告 |
| `--color-danger` | `#B33A3A` | 错误和危险操作 |

具体实现可在对比度验证后微调色值，但语义角色不得改变。

### 3.2 排版

- 正文字号 14px，紧凑表格 12–13px；
- 页面标题 22–24px，不使用超大宣传标题；
- 区域标题 16–18px；
- 正文行高至少 1.4；
- 中文正文使用系统无衬线字体栈；
- 等宽字体只用于 ID、版本号和技术状态；
- 粗体只用于阅读层级和关键数字。

### 3.3 间距与形状

- 基础间距单位为 4px；常用间距为 8、12、16、24px；
- 页面内容间距 20–24px；
- 控件高度默认 36px，紧凑表格控件可为 32px；
- 圆角以 4–6px 为主，不使用大面积胶囊形；
- 阴影只用于浮层和固定操作栏，普通区域使用边框分层。

## 4. 全站页面外壳

### 4.1 桌面端

- 稳定左侧导航；
- 紧凑顶部栏显示站点、环境、时区和账号；
- 内容区顶部统一显示返回路径、页面标题、范围/日期、状态和主要操作；
- 主内容占据首屏，不在数据表前重复大段业务宣传。

### 4.2 窄屏

- 768px 以下导航折叠；
- 页面标题和主要操作分行但保持首屏可见；
- 筛选栏可以换行或打开筛选面板；
- 宽表保留横向滚动，不转换成不可比较的卡片列表。

## 5. 统一组件

### 5.1 按钮

- 主要按钮：每个操作区最多一个；
- 次要按钮：普通导航和低风险命令；
- 危险按钮：删除、停用和不可逆操作；
- 文字按钮：表格行内和轻量入口；
- 加载、禁用、聚焦和失败状态统一。

### 5.2 表单

输入框、选择器、日期范围和文本域统一高度、标签、帮助文本、边框、聚焦环、
错误提示和只读状态。标签不能只依赖 placeholder。

### 5.3 数据表

所有主要表格共享：

- 表头和边框令牌；
- 冻结列视觉；
- 排序、分页和筛选布局；
- 空、加载、失败和无权限状态；
- 行悬停、键盘焦点和当前行；
- 修改、冲突、校验和发布状态色。

简单管理列表不强制使用复杂两层表头或列调宽；只有超宽业务表使用结构增强网格。

### 5.4 标签、提示与弹窗

状态徽标使用低饱和背景和明确文字。提示条按信息、成功、警告、错误区分。
弹窗标题、正文、风险说明和按钮顺序保持一致；高影响操作继续要求明确确认。

## 6. 页面级调整

### 6.1 首页发布总表

- 移除或压缩大标题和重复说明；
- 每日总表、产品总表和发布明细成为首屏主导航；
- 日期范围、状态说明和主要筛选位于统一工具栏；
- 表格和空状态占据主要空间。

### 6.2 日期工作台

应用结构增强表格设计。上传、识别确认和审核操作使用统一控件；高级审核区降低
视觉层级，但保留原有恢复能力。

### 6.3 版本记录

统一筛选栏、版本状态、父子关系、当前发布标记和操作按钮。历史关系仍使用现有
业务模型，不用纯颜色表示版本状态。

### 6.4 管理员控制台

账户、站点配置、备份和任务使用一致的区域标题、表单和数据列表。权限、幂等键、
确认流程和审计读取不改变。

### 6.5 旧导入审核

统一样式并减少重复宣传内容。它继续作为高级审核和恢复入口，不重新成为日期页
的默认主流程。

## 7. 状态与反馈

全站统一处理：

- 首次加载与局部加载；
- 空数据；
- 成功；
- 警告；
- 阻断错误；
- 离线或网络不确定；
- 权限不足；
- 并发冲突；
- 高影响操作进行中。

状态必须有文字，不以颜色或动画作为唯一表达。减少动画偏好下关闭非必要过渡。

## 8. 实施边界

建立共享令牌和基础组件后分阶段落地：

1. 页面外壳和结构增强日期工作台；
2. 跨日期发布明细总表；
3. 首页其他总表；
4. 版本记录；
5. 管理员控制台；
6. 旧导入审核区域。

每个页面迁移后独立运行现有业务回归测试。不得在视觉迁移中同时重写业务服务、
权限或版本事务。

## 9. 无障碍与响应式验收

- 所有交互具有可见键盘焦点；
- 正文和交互文本达到 WCAG AA 对比度；
- 200% 缩放下主要操作可用；
- 触控目标不因高密度小于可用范围；
- 图标按钮具有可访问名称；
- 表格保留语义行列关系；
- 1280、768 和 390px 下无页面级横向溢出，业务宽表仅在自身容器内滚动；
- 固定底部操作栏不遮挡最后一行或系统浏览器控件。

## 10. 测试与视觉门禁

### 10.1 自动化

- 设计令牌和组件状态测试；
- 页面结构与角色可见性回归；
- 键盘导航、焦点和弹窗行为；
- 1280、768、390px 响应式组件测试；
- 现有前端测试、lint、typecheck 和生产构建。

### 10.2 浏览器验收

对首页、日期工作台、发布明细、版本记录和管理员控制台逐页检查：

- 首屏任务是否明确；
- 是否只有一个突出主操作；
- 空、加载、错误和无权限状态；
- 表格、表单和弹窗一致性；
- 键盘焦点、200% 缩放和减少动画；
- 桌面、平板和手机宽度。

## 11. 完成标准

- 全站使用同一套蓝白语义令牌和基础组件；
- 大标题、过量留白和装饰性视觉不再压过数据任务；
- 首页、工作台、总表、版本记录和管理页面具有一致的操作层级；
- 业务流程、权限和版本安全语义没有因视觉迁移改变；
- 所有必需状态和响应式尺寸通过自动化与真实浏览器验收。
