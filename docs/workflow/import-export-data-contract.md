# 导入导出数据约定 v1.0

生效日期：2026-10-16。性质：用户要求的长期项目开发约束，适用于当前及后续涉及导入、提取、整理、模板、导出和再导入的功能。约定建立不代表相应代码已经实现或历史数据已经符合；实际版本、授权与进度仍只维护[当前执行卡](project-plan-index.md#current-execution)。

本约定与[商品身份与业务关联约定](product-identity-and-linkage-contract.md)、[库存数量合同](../superpowers/plans/2026-10-13-inventory-ledger-and-dispatch-availability-plan.md#inventory-quantity-contract)共同适用。人工表格的具体实施任务只维护[原表提取与整理模块方案](../superpowers/plans/2026-10-16-manual-table-extraction-and-normalization-plan.md)。

## 1. 资料来源与既有兼容

| 资料 | 使用路径 | 长期边界 |
| --- | --- | --- |
| 平台官方原始输出，如经营报告、退货报告 | 该平台已有或专门适配的导入器 | 保持来源、账号/站点、报表类型、期间和字段权威；官方解析失败不自动转入人工整理后作为同等官方证据 |
| 已能正常运行的标准模板、固定原表 | 原有入口、接口与解析规则 | 不因新增人工整理而重写、替换或强制迁移；必要维护须按对应任务明确影响范围 |
| 人工编制或人工改排的仓库、订单、装箱等表格 | 明确标识的人工表格整理入口 | 提取所需字段、保留原文及位置，形成标准明细和异常清单，再交业务模块校验 |

来源性质由业务声明和可验证的结构共同确定，不以.xlsx后缀、文件名含“亚马逊”或用户手动上传判断。官方文件的人工修改副本注明已整理，不继承原始官方证据级别；原始官方副本可单独保留并走原流程。来源无法确定时保存待核，不自动提升权威。

后续新入口须写明所属路径。新增模块默认复用已有有效业务校验和组件，增加必要接入点，不顺手整治不受影响的旧导入器、旧导出器或历史数据。

## 2. 原件、明细与业务事实

- 原件不可被清洗结果覆盖；来源摘要、文件名、上传人、时间和适用范围可追溯，原件下载继续经过权限检查，不暴露服务器路径。
- 提取后的每条明细保留来源工作表、物理行号及关键单元格；拆尺码、合并重复行、排除小计等变换保留对应依据与原始行覆盖，不静默丢行。
- 原文、规范化候选、人工确认值分开保存。图片、配色、字体、列宽等展示样式一般不参与商品身份或数量判断；涉及行列含义的合并单元格、隐藏行和分组需明确处理。
- 表头对应方案只说明哪列是什么字段，不是商品映射、颜色别名、空白数量或日期口径的永久确认。再次应用时须核对结构；不同站点和来源不自动共享。
- 读取成功、整理完成、保存草稿、商品关联、业务确认、过账与正式发布分别表达。整理或导出不产生订单、库存、平台关联或报表发布事实。

## 3. 字段、身份与中文错误

1. 模板、解析、页面预览和可回导明细使用同一份该模块字段定义及模板版本；列名、类型、必填阶段、单位和数量含义保持一致。不同业务可有不同必要字段，不建立含糊的万能“SKU/数量”合同。
2. stable style_id/sku_id连同site/账号/站点范围和目录版本由服务端校验。Seller SKU、工厂编码、ASIN、FNSKU及款号分别解释；不将工厂基础码或相似名称自动当作Seller SKU。
3. 沿用项目公共规范化版本。Seller SKU匹配与实体款色尺码匹配不可互换；禁止以清洗名义静默改写编码大小写、前导零、颜色或身份归属。
4. 数量须符合业务的整数、符号与零值规则；空白、0、“/”、未知和不适用分开。已有明确的仓库/来源口径可以带入，并在预览中注明；不把某批空白=0推广至其他资料。
5. 日期按列的业务含义读取，不将文件名、修改时间、导出时间、DELIVERY或预计日期代替实际发生日期。未知允许在整理草稿保留，业务确认前补齐目标模块真正需要的字段。
6. 合计依据已识别明细独立重算，不把小计、箱内分配和总数重复累加，不执行上传文件的宏、外链或任意公式。公式缓存不单独成为数量权威；支持的摘要计算与不支持的公式应明确区别。
7. 问题返回稳定代码、中文说明、工作表/行/列、原值、影响及可执行的修正方法。页面可定位并按问题筛选，错误文件可下载；不向用户裸露英文异常或堆栈。
8. 自动完成可证实的格式整理；数量矛盾、商品冲突、未确认颜色及缺少事实不得靠猜测修复。用户排除明细时记录理由、行数及数量影响。

## 4. 快照、需求与事件

- 库存表是指定范围和时点的结存；预下单是预计需求；装箱和实际出货按其状态确认。三者不直接相加减成业务事实。
- 同一快照不能当新增入库重复累加。已确认包含某次实际出货的结存，后续补录该历史出货不能再扣库存；依赖现有数量合同核对事件覆盖及关联范围。
- 发货仍由库存唯一写入服务按当时可发及本次自有预留校验；预计量、报表销量、差额或整理结果不提供放行依据。
- 文件摘要只识别字节完全相同的文件。换名、改格式或重新导出不证明新业务；事件来源、单据关联、稳定操作ID及显式更正继续防止重复记账。
- 重新导入先明确是新事件、同一资料的再次核对还是原记录更正。已发生业务的历史不由新文件直接覆盖或删除。

## 5. 导出及再次导入

| 导出用途 | 必须说明与保留 | 再导入方式 |
| --- | --- | --- |
| 原件下载 | 原始字节、来源和权限 | 按原来源规则处理，不把下载动作当新业务 |
| 标准明细/模板 | 模板版本、字段定义、明细粒度、单位、资料性质、业务日期/截止、适用范围及必要来源引用 | 由对应版本解析器校验；同一资料不增加第二笔事实，修改走更正 |
| 业务查看用宽表 | 与其适配器一致的款色、尺码、数量和仓库等列；变换和未知项有说明 | 只有明确列入支持范围的宽表可回导；不承诺复制任意原件样式 |
| 汇总/分析报表 | 汇总粒度、筛选、口径、时区、统计期间及源版本 | 明确“汇总查看，不可直接作为业务明细导入” |
| 问题清单 | 原表位置、问题、原值、处理建议及确认状态 | 定位原批次处理，不能绕过校验成为入账依据 |

- 可回导文件的数据页保持可解析：标识符为文本，数量和日期类型明确，说明与小计不混进明细。标题、字体等样式不携带必要业务含义。
- 后续新增导出采用一致的中文字段、文字编码格式、清楚的单位、冻结表头和适当列宽；样式服务于阅读，不能补造缺失值。已正常运行的旧导出不因本约定自动改版。
- 原始标识符保留，安全输出为文字，防止以“=”“+”“-”“@”等起始的原文被Excel当作公式执行；不以改变业务编码来规避。
- 导出使用一致的来源/修订，注明筛选和覆盖分页范围。不得把当前一页冒充全部，不静默漏掉未匹配或待核项；待核项应在明细或问题清单可见。
- 稳定ID和来源引用即使写入导出文件，再导入仍不受信任；重新检查权限、scope、当前目录和单据状态。导出文件不携带凭证、服务器路径或无关私有信息。
- 导出范围遵守读取权限，下载原件与导出业务明细分别检查。用户操作历史可追溯导出人、时间、范围与对应修订。

## 6. 权限、并发和交付

- 页面能力与服务端权限一致；客户端提交的site、actor、sku_id或目标单据ID不构成授权。管理员查看操作记录仍受所属站点范围限制。
- 保存/移交/业务确认使用稳定操作ID、内容摘要和预期修订；相同操作重放返回原结果，不同内容拒绝。恢复时先查询原结果，不换ID盲重试。
- 整理模块只写自己的资料与决定。Python主档、Java业务事实及平台官方报表各保留唯一责任；转换草稿不绕过其业务开关或当前授权。
- 文件预算、类型及资源限制沿既有能力，变更需有当前输入依据；复用已有依赖，不默认接入外部AI/OCR或发送真实文件。
- 验证按[统一策略](../operations/development-verification-policy.md)覆盖本次完整路径、直接相关旧入口、来源/权限/数量/重复及承诺的导出回导。未改变的有效结果复用，不以该约定要求全仓重测或历史全面整改。
- 普通任务在原任务中说明适用字段、业务写入方、旧路径影响及必要验证即可，不增设审批表、通用导入平台或每次导出全套检查。既有真实数据读取、写入、迁移和发布授权继续适用。

## 7. 后续功能的执行方式

凡后续新增或修改导入/导出，在任务方案或交付说明中直接回答：来源走哪条路径；提取/输出哪些字段；哪些值可以自动整理；哪些业务问题需确认；能否回导、如何防重复；旧入口是否受影响。无关项注明不适用即可。

本约定在AGENTS、开发流程及商品身份合同中建立入口，不能仅作为某轮执行卡备注。具体模块新增字段或适配器须与此约定一致；当前未实现的要求只能写为待实施，不宣称已具备。
