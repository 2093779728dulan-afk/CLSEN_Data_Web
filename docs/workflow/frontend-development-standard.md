# 前端设计与依赖执行规范

2026-10-21。适用于后续前端任务；任务范围与版本来源仍以[当前执行卡](project-plan-index.md#current-execution)为准，验证沿[验证策略](../operations/development-verification-policy.md)。

## 基本取舍

优先复用成熟库和已有组件，组件源码由项目控制，统一设计语言，严格限制重复依赖。先查目标工作树的 package.json、lockfile、design-system 和实际消费者，再决定复用、适配源码或按需引入库；不能只查主工作区就推断 A/B 的依赖情况。

复用顺序：项目已有公共组件 → 已选成熟库／上游组件源码 → 有具体缺口时自行实现。复杂焦点、弹层、拖拽等交互优先使用成熟实现；原生 HTML、CSS 已足够的行为可直接保留。业务规则、权限、稳定 ID、修订和写入合同仍由项目代码负责。

## 页面间导航与入口一致性

2026-10-29按用户明确要求统一：未经用户允许，不得临时插入没有套用组件样式的链接。

- 页面返回、跨模块办理、页头操作优先使用现有 `LinkButton`、导航组件及页面动作槽位；正文或表格中的链接可沿用已确认组件的父级样式，不以“没有自己的className”直接判错。文件下载保留原生链接与下载语义，同时采用对应组件样式，不改成前端路由。
- 同一页面在相同权限、数据与屏幕宽度下，从侧栏、总览、业务关联入口、直接URL及刷新进入，页面外壳、导航位置、间距和组件样式应一致。业务权限、数据状态及明确URL筛选可以影响其各自内容，不把合法差异混为界面缺陷。
- 进入来源、返回地址、筛选及焦点恢复状态只影响对应目标和状态恢复；不得依此临时增加或删除整段返回栏、正文链接、额外留白或另一套页面布局。返回入口使用稳定槽位，缺少来源上下文时按已确认的页面归属回到默认入口；加载态也保留对应导航位置。
- 禁止用裸 `<p><Link /></p>`、未套组件样式的独立 `a/Link`、临时行内样式或宽泛全局选择器补出页面间导航。已有入口缺样式时修正其组件使用和布局归属，不能用临时插入一行代替。
- 未经用户明确同意，不新增临时导航栏、重复返回入口或改变已确认页面结构。当前授权内沿既有固定槽位修复、替换为已有组件，不按每个文件或每个按钮重复审批。
- 导航或共用布局变更时，定向比较直接进入、上下文跳转和刷新，核对返回后筛选保留、适用加载/空/失败状态及窄屏、键盘焦点。复用仍有效结果；检查结论须区分源码检查、浏览器实测与用户确认，不宣称全页面验收。

## 默认选型与边界

| 能力 | 默认选型 | 使用边界 |
| --- | --- | --- |
| 框架与路由 | React、TypeScript、Vite、React Router | 沿用现有架构及版本锁定，不并行引入另一套应用框架 |
| UI 组件 | 项目自有的 shadcn/ui 派生 Design System，复杂交互使用既有 Radix | 业务页面从 design-system 公共入口复用；上游源码适配项目 props、Token 与 CSS Modules，Radix 留在组件内部 |
| UI 风格 | 已确认的 CLSEN 中性工作台：浅色背景、白色表面、深灰文字、蓝色主操作与焦点 | 统一字体、密度、圆角、间距、语义色、状态反馈；Nova 为候选视觉预设，尚未固定准确来源和配置，不据名称覆盖现有主题 |
| 图标 | Lucide，包名 lucide-react | 按图标导入，复用现有尺寸、线宽和颜色；图标按钮有可访问名称，装饰图标不重复播报 |
| 动画 | Motion，入口 motion/react；简单 hover/focus 使用 CSS | 优先复用已有 ContentReveal、PageTransition、RouteNavigation 等；时长与缓动取 Token，支持 reduced motion，保留刷新时的焦点和内容，不以动画模拟操作成功 |
| 普通布局 | CSS Grid、Flex、现有 CSS Modules | 响应式页面不需要额外布局库；数据表局部横向滚动，不让整页溢出 |
| 可调整分栏 | react-resizable-panels | 需要用户调整双栏／多栏时按需接入，约束最小尺寸并提供键盘可操作的分隔条；不承担普通页面布局或表格列宽调整 |
| 复杂拖拽 | dnd-kit | 跨容器、触摸、排序反馈等需求出现时优先采用；核对实际包族、版本与 API，统一一条接入路径；提供键盘或按钮替代，拖动后按原保存合同落地 |
| 客户端共享状态 | Zustand | 多组件／跨区域共享且本地 state、提升状态或既有 Context 已不合适时接入；按领域和生命周期划分 store，避免全应用单一大 store |
| 本地、流程与 URL 状态 | useState、useReducer、已有 Context、React Router | 本地控件留在本地，复杂单页流程沿 reducer；可恢复的筛选、日期、分页沿 URL；权限 Context 保留既有清理职责 |
| 服务端数据 | 现有 API 客户端与读取控制器 | Zustand 不代替服务端事实、请求一致性、权限失效或版本校验，不为选型统一再复制一份服务端数据权威 |
| 图表与展示样板 | ProductTrendChart 既有参考与 Storybook | 沿用已确认折线图及样板合同，使用虚构数据；按任务影响范围维护状态与页面覆盖 |

选型表确定后续需求的优先实现方向，不表示所有库都已安装，也不要求每个页面使用所有库。已有 UI 来源在 2026-10-21 核对时包含 Radix、Lucide、Motion；未声明 react-resizable-panels、dnd-kit、Zustand。首次接入时按任务核对兼容性并锁定实际依赖，具体版本以目标工作树 package.json/lockfile 为准。

如后续明确采用 shadcn/ui Nova，应先固定其官方／registry 来源、预设配置、基础 primitives、样式方案及与现有 Token 的映射。当前项目采用受控源码和 CSS Modules；不因使用 shadcn 名称直接执行初始化覆盖或追加整套样式工具链。可先在对应任务的代表性页面确认视觉，再逐步复用。

## 组件源码与重复依赖

- 共享组件源码放在项目 Design System，业务页面组合组件，不复制另一套 Button、Dialog、表单或反馈实现。只为稳定的项目使用方式提供薄封装，不预建通用适配平台。
- 引用上游源码时核对准确 API、来源版本／提交及许可证，在已有第三方说明中记录必要适配。源码可控不等于复制并维护成熟库的全部内部实现。
- 同一能力原则上只用一套主要方案：新图标用 Lucide，JS 动画用 Motion，复杂拖拽用选定的 dnd-kit 包族，客户端共享 store 用 Zustand。库的必要子包和正常传递依赖不等于重复方案；CSS 与 Motion 分工也不属于重复引库。
- 新增直接依赖只说明具体缺口、现有方案不能满足的原因、实际包与兼容版本、许可及明显体积影响，写入原任务说明；不为普通选型另建审批台账，也不机械要求每次测量完整 bundle。
- 不同时新增第二套 UI 系统、图标集、JS 动画、拖拽或全局状态库。确有不兼容的必要能力时，在原任务中明确例外用途与适用范围；会实质改变全站设计或公共架构的决定再向用户确认。
- GlideSelect 已有 Hugeicons 两包属于既有组件来源例外，保留当前功能及历史确认；新代码不扩大使用。替换仅在对应组件任务中处理，确认实际消费者移除后再删除依赖，不因规范整理开展全仓替换。

## 状态、体验与渐进应用

- 以服务端响应、稳定 ID 和修订为业务依据；禁止通过拖拽、动画或 store 更新绕过权限、幂等、并发及业务确认。未知、缺报、真实零和读取失败分别展示。
- 筛选与刷新保留原 URL 合同、输入和焦点。权限／用户／站点变化时清理对应敏感状态；不把临时表单或敏感服务端结果默认持久化到浏览器存储。
- 修改组件同时考虑桌面、平板、窄屏、键盘、焦点返回、loading、空、失败与恢复。共享展示用于实际页面与 Storybook，避免样板实现和业务实现各自演进。
- 新功能及被本次修改的组件按本规范实现；已确认且未受影响的页面、原生拖拽、reducer、Context 和兼容样式保留，不以统一选型为由全量迁移。
- 页面内部布局、共享导航和全局主题是不同改动范围。只优化页面时保留既有外壳与折叠偏好，参考图中的周边界面不自动成为实现目标；已有选稿或局部修正不强制进入外部视觉检索、新配色或探索流程。
- 后续规范优化不向 A 待发布版本自动增加依赖、重做主题或同步 B 新功能；既有用户确认、正式门禁和发布授权保持。具体来源变更沿原任务执行。
- 验证复用现有入口和仍有效结果。共享样式、依赖、布局或交互变化按直接消费者扩大检查；纯规范文档只核对差异与链接，不新增测试平台、重跑业务或更新视觉基线。
