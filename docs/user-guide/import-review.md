# 数据管理员：导入、审核与修订

系统不会把上传表格直接发布。每个报告日独立维护原文件、解析结果、草稿、人工修改、备注、校验和发布版本。

## 日常流程

1. 在左侧日期轨选择目标日期。上传时再次确认报告日期和报表类型。
2. 上传原表后查看系统识别结果，包括表格类型、检测日期、行数和汇总值。
3. 人工确认识别无误后才执行解析。识别错误时先更改日期或重新选择文件，不要为了迎合系统修改真实业务值。
4. 在草稿表格中对照“原表值 / 基线值 / 当前值”。只有应用录入错误时才修正字段、补行、排除错误行或恢复原值。
5. 通过批次备注或数据备注补充原因。备注采用追加修订，不覆盖旧内容。
6. 运行完整校验，处理阻断项并判断警告。确认行数、报表类型、日期和汇总值后标记为待发布。
7. 发布后数据才进入经营看板。后续修订会创建新版本，旧版本和原文件始终可追溯。

## 日期隔离

- 选择某一天只改变当前工作区，不影响其他日期。
- 更改草稿所属日期会创建受审计的日期迁移，不会静默覆盖目标日期。
- 目标日期已有活动草稿或已发布版本时，系统先展示冲突预览；必须明确选择合并、替换或取消。
- 任意一天都可以重新打开并基于已发布版本创建修订；新修订发布前，看板仍显示原发布版本。

## 应当修改什么

可以修改：

- 系统解析或字段映射造成的录入错误；
- 原表确有遗漏、且业务已确认需要补录的行；
- 行状态和解释性备注；
- 上传时选错的报告日期。

不应修改：

- 原表与真实业务一致、只是结果“不好看”的数据；
- 为消除校验警告而没有业务依据地改值；
- 已发布历史版本本身。应创建后续修订版本。

## 常见状态

- `draft`：仍可修改，尚未通过人工确认。
- `ready`：已完成当前校验和确认，等待发布。
- `published`：当前对查看人员和看板可见。
- `superseded`：已被后续版本替代，但仍保留。
- 红色日期：存在阻断、失败或原文件完整性问题。
- 黄色日期：有活动草稿、警告或处理中任务。
- 蓝色日期：两类报表只有一类已发布。
- 绿色日期：经营和退货报表均已发布。

遇到不确定冲突时优先取消操作，核对原表和目标日期后再继续。管理员的强制重建也不会绕过重新校验和人工确认。
