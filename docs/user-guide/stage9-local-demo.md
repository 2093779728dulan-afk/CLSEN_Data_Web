# 阶段 9 本地体验

本教程用于在本机体验阶段 8–9 的网页流程：选择日期、导入与审核 CSV、发布普通版本、查看版本记录和经营看板，以及管理员专用的冲突恢复与已发布跨日期移动。

## VS Code 快捷启动

如果 `.env` 中的普通本地开发数据库和账号已经准备好，可直接用 VS Code 打开仓库根目录，然后：

1. 打开“运行和调试”（`Ctrl+Shift+D`）。
2. 选择 `启动本地应用`。
3. 按 `F5`，VS Code 会并行启动 FastAPI 和 Vite。
4. 访问 <http://127.0.0.1:5173>；按 `Shift+F5` 停止本次 F5 启动的两项服务。如果端口仍被占用，在终端工具栏中终止对应终端。

也可以按 `Ctrl+Shift+B` 运行默认任务 `CLSEN: 启动本地应用`，它会并行启动后端、前端和负责退货去重、发布发件箱及商品目录导入导出的 Worker。若只需要单个进程，可在“终端 → 运行任务”中选择对应任务。F5 和构建任务是两种等价入口，请二选一；切换入口前先停止原来启动的服务，避免重复占用 `8000` 和 `5173` 端口或重复运行 Worker。任务方式启动后，应使用“终端 → 终止任务”停止服务。需要让 Worker 使用测试库时，请在终端运行 `.\scripts\run-worker.ps1 -UseTestDatabase`。

快捷启动只调用现有 `scripts/dev-backend.ps1` 和 `scripts/dev-frontend.ps1`，使用 `.env` 的 `APP_DATABASE_URL`，不会创建账号、迁移数据库或写入演示数据。它是普通本地开发入口，不是隔离的阶段 9 测试库入口。第一次体验隔离测试数据时，仍先按下文运行 `stage6-demo.ps1` 和 `start-stage9-demo.ps1`；后者需要安全地交互输入新账号密码，不纳入一键启动。

普通本地库的初始管理员账号是初始化数据库时填写的用户名。如果忘记密码，可先停止后端，再在 PowerShell 7 中运行：

```powershell
cd D:\CLSEN_Data_Web
.\scripts\reset-admin-password.ps1 -Username TCJ
```

按提示输入两次至少 12 位的新密码。密码不会显示、写入命令历史或保存到 `.env`；重置成功后，该账号已有的登录会话会全部失效，角色和账号状态不会改变。此命令读取普通本地库的 `APP_DATABASE_URL`，不操作阶段 9 隔离测试库。

如果命令提示普通库迁移版本低于当前要求，先停止前后端，在 PowerShell 7 中运行下列现有库升级命令，并在凭据窗口中填写 MySQL 管理员账号（通常为 `root`）及其密码：

```powershell
& 'D:\CLSEN_Data_Web\scripts\init-database.ps1' `
  -AllowExistingPrimaryDatabase `
  -ForceEnvironmentFile `
  -SkipApplicationAdmin
```

该命令保留现有 `clsen_data` 业务库，通过 Alembic 升级结构，同时轮换本地专用数据库账号密码并将新连接信息写入受保护的 `.env`。升级成功后再运行密码重置命令。

## 安全边界与前提

演示入口只接受本机 `clsen_data_test` 或 `clsen_data_test_<suffix>`，原始文件保存在 `data/raw/stage6-demo`。它不会迁移、读取或写入正式 `clsen_data`，也不会自动清空测试数据。

开始前确认：

- 使用 PowerShell 7（`pwsh`），不是 Windows PowerShell 5.1；
- 仓库根目录已有 `.env` 和 `.venv\Scripts\python.exe`；
- 测试库已经按项目当前迁移与最小权限清单准备好；迁移新增表后，在 PowerShell 7 中运行 `.\scripts\sync-test-runtime-grants.ps1`，按安全提示输入 MySQL 管理员凭据，同步并核对低权限运行账号；该脚本只接受本机 `clsen_data_test*`，不运行迁移，也不访问正式库；
- 准备一个至少 12 位的演示密码，并为每次新建账号使用尚不存在的用户名。脚本不会重置同名账号。

## 1. 准备隔离演示数据

在 PowerShell 7 中执行：

```powershell
cd D:\CLSEN_Data_Web
.\scripts\stage6-demo.ps1 -PrimaryDate 2026-08-01 -IsolationDate 2026-08-02
```

该命令会在主日期保留一份已发布的合成经营报告，并在隔离日期保留一份未发布审核草稿，便于同时体验看板、版本记录、审核状态和日期隔离。它的终端提示如果说“阶段 7 API 和阶段 8 UI 未启动”，只是说明这个阶段 6 脚本本身不启动网页服务。

## 2. 创建演示账号并启动 API

如果只体验一个角色，在第一个 PowerShell 7 窗口运行对应命令并保持窗口开启：

```powershell
cd D:\CLSEN_Data_Web
.\scripts\start-stage9-demo.ps1 -Username stage9-admin-01 -Role admin
```

脚本会分别提示输入和确认新密码；密码不会显示或写入 `.env`。账号创建后，API 在 <http://127.0.0.1:8000> 启动，并明确使用低权限测试库连接。

如需对比三个角色，依次执行以下命令。每次看到 API 成功启动后按 `Ctrl+C` 停止，再执行下一条；最后一个命令保持运行。记住每个账号各自的密码。

```powershell
.\scripts\start-stage9-demo.ps1 -Username stage9-admin-01 -Role admin
.\scripts\start-stage9-demo.ps1 -Username stage9-manager-01 -Role data_manager
.\scripts\start-stage9-demo.ps1 -Username stage9-viewer-01 -Role viewer
```

若某个用户名已经存在，脚本会在启动 API 前拒绝继续。请改用新的后缀，不要删除或覆盖已有账号。

## 3. 启动前端并登录

在第二个 PowerShell 7 窗口运行：

```powershell
cd D:\CLSEN_Data_Web
.\scripts\dev-frontend.ps1
```

访问 <http://127.0.0.1:5173>，输入刚创建的账号和密码。需要切换角色时，点击左侧底部的“退出”，再使用另一个演示账号登录；API 无需重启。

## 4. 体验普通导入、审核与发布

使用管理员或数据管理员账号操作：

1. 进入“数据审核”，从左侧每日证据轨选择一个空闲报告日。不同日期拥有独立的导入、草稿和发布指针。
2. 在“所属报告日”确认或调整日期，选择一份或同时选择多份 CSV。可以使用仓库内的去标识化样本 `backend\tests\fixtures\synthetic\business-report.csv` 或 `backend\tests\fixtures\synthetic\return-report.csv`。
3. 点击“保存并检查文件”。多份文件会被逐份保存和识别，并显示在批量导入队列；一份失败不会撤销已经保存的其他文件。每份原始文件都是独立的不可变导入批次，不会直接进入看板，也不会因为批量选择而自动确认。
4. 在“人工确认识别结果”中核对报表类型、日期和编码；需要时先修改日期，再点击“确认并解析”。
5. 检查解析行数，填写“生成草稿原因”，点击“生成审核草稿”。系统会先读取目标日期现有发布版本和活动草稿，再决定直接创建草稿还是显示冲突选项。选择合并时，如果目标行和来源行具有相同业务指纹，页面会显示完整的“目标行 × 来源行”决策矩阵；每一对都必须明确选择保留目标、保留来源或两行都保留，并填写判断依据，未完成的矩阵不能提交。
6. 在审核表中对照源值、基础值和当前值。表格由服务端每页读取 50 行；SKU/ASIN 等关键列固定显示，并支持当前页搜索、过滤、表头排序、字段聚焦、上一处/下一处差异和方向键单元格导航。当前页没有差异时，可关闭“仅看差异”。
7. 点击单元格打开对照抽屉。纠正导入错误时填写原因后修改当前值；也可追加备注，或按证据恢复上次修改、父版本值或源文件值。原表业务值如果已正确，不需要为了“制造差异”而修改。
8. 点击“运行完整校验”，处理阻断项并确认需要人工说明的警告。校验通过后填写“审核确认说明”，点击“确认结果并标记待发布”。
9. 普通草稿可由管理员或数据管理员打开发布确认。核对日期、报表类型、行数、合计、警告和版本，填写发布说明后确认发布。
10. 进入“已发布看板”，选择统计月份，查看经营指标、每日趋势、SKU/ASIN 排名和退货构成。切换“报告所属日/退货事件日”可观察退货归日口径；“本次统计依据”列出实际发布版本与站点配置版本。页面顶部的站点名称、币种、源时区和统计时区来自当前版本化站点配置，不依赖电脑或浏览器时区；管理员创建新的当前配置后，页面会重新读取该上下文。
11. 进入“版本记录”，按日期和报表类型查看当前发布、活动草稿、不可变版本谱系和查看人员可见备注。

## 5. 体验导入冲突中的管理员强制重建

这项操作只能从经过服务器预览的导入冲突进入，不能在管理员控制台手工填写版本或数据库 ID。

1. 先在某个日期生成活动草稿，但暂不发布。
2. 以管理员身份导入另一份同报表类型、可识别且内容不同的 CSV，并把它分配到同一日期。
3. 目标预览显示活动草稿后，选择“管理员强制重建活动草稿”。填写生成草稿原因，并勾选“确认废弃目标活动草稿并保留审计历史”。
4. 点击“强制重建审核草稿”。旧草稿、修改和备注仍保留在审计历史中；新草稿必须重新完成校验、人工确认和发布。

数据管理员会看到目标冲突，但不会看到管理员强制重建选项。替换普通发布版本也只是创建新草稿，发布指针在最终审核发布前不会改变。

## 6. 体验废弃草稿并重新解析来源文件

当识别类型、编码或解析结果有误时，不要在原草稿上伪造业务修改来掩盖解析错误。使用管理员或该草稿的创建者账号：

1. 在活动草稿的审核区点击“废弃或重新解析当前草稿”。
2. 填写废弃原因，并勾选“我确认当前草稿将被废弃，历史记录不会删除”。
3. 只想结束本次审核时，点击“仅废弃当前草稿”。版本会变为 `discarded`，旧基础快照、人工修改、备注和审计仍然保留。
4. 需要修正解析时，点击“废弃并重新解析来源文件”。系统先以幂等命令废弃活动草稿，再恢复它引用的来源批次，让你重新确认报表类型、所属日期、编码和站点配置。
5. 点击“确认并解析”会创建新的不可变解析尝试和解析基线；旧草稿仍固定引用原解析基线，不会被新结果重写。确认新解析正确后，再生成并审核一份新草稿。

已经成功解析但尚未生成草稿的批次，会明确显示当前所属日期。若发现把 7 月 1 日的原表错误分配到了 7 月 5 日，可点击“修改日期并重新解析”，回到识别确认后采用识别日期或手工选择正确日期，再次确认解析。系统会创建新的不可变尝试和基线，旧日期的解析证据不会被覆盖。失败解析也不会替换该批次最后一次成功基线。

批量队列始终只把一份文件置于当前审核区。核对并发布当前文件后点击“审核下一份文件”；也可以在尚未生成草稿时从队列选择另一份等待中的文件。队列保存在当前浏览器标签页的会话存储中，刷新或暂时离开页面后会恢复；关闭标签页会清除本地队列，但所有已经上传的原始批次和已提交的服务端操作仍然保留。

## 7. 体验已发布数据跨日期移动与撤销

先使用管理员账号；可以选择第 1 步准备的 `2026-08-01` 当前发布经营版本作为来源。

1. 进入“版本记录”，筛选来源日期和报表类型，选择当前发布版本，点击“移动到其他日期”。来源日期如果已有活动草稿，必须先完成或废弃该草稿。
2. 选择目标报告日并点击“检查目标日期”。根据目标状态明确选择合并、替换、取消，或在目标已有活动草稿时选择管理员强制重建；填写移动原因后创建跨日期审核草稿。
3. 系统跳转到目标日期的“数据审核”。此时来源版本仍保持发布，目标只是一份活动草稿。
4. 对目标草稿执行与普通草稿相同的逐行审核、完整校验和人工确认。数据管理员也可以参与这段审核，但不能执行最后的发布指针切换。
5. 重新以管理员身份打开目标草稿，点击“打开跨日期生效确认”并确认。系统在一个事务中同时撤下来源发布指针并切换目标发布指针；任一步失败都不会只改变一侧。
6. 生效后在“版本记录”选择目标当前发布版本。若两侧指针仍满足撤销前置条件，会显示“撤销跨日期移动”。填写撤销原因并确认后，系统在一个事务中恢复两侧发布指针；任一日期已有新发布或活动草稿时，整个撤销会被拒绝。

## 8. 体验跨日期批量审核

使用管理员或数据管理员账号，在同一次导入队列中至少保存两份 CSV 后，队列会出现“批量审核”入口。重复上传返回的已有未完成批次也可参加，但同一服务器批次只会提交一次；尚未保存成功的本地文件不会进入预检。

1. 点击“批量审核”进入独立的 `/review/batch/:runId` 页面。清单中的文件名、批次号、日期、报表类型、编码、识别状态和目标占用均由服务器重新读取，不采用浏览器提交的显示值。
2. 合格项目默认选中；识别不确定、目标重复、已有活动草稿、已有发布版本或来源不可用的项目不可选，并显示人工处理原因。可主动取消不想在本次推进的合格项目。
3. 勾选“我已核对所选文件的报告日期和报表类型”，再点击开始。确认事务会再次检查目标状态；确认后出现的新冲突不会被覆盖，而会转入人工处理。
4. 页面最多同时推进三项，依次完成确认解析、草稿生成、完整校验和标记待发布。一项失败或出现校验警告不会停止其他项目；任何警告都不会被自动确认。
5. 点击“暂停批量处理”后不会领取新项目，已经发给服务器的项目会安全结束。刷新或重新登录后，页面先读取服务器任务再恢复；它不会依据旧的 React 内存状态猜测完成结果。
6. 只有服务器标记为“可重试”的临时失败才显示“重试”。业务冲突和校验异常使用“处理异常”进入已定位日期、报表类型和（若已生成）版本的现有审核页。
7. “查看全部待发布草稿”进入按本任务服务端筛选的版本列表。这里的完成含义是 `ready_for_publish`，不是 `published`；仍需通过现有发布确认，批量流程从不切换发布指针。

第一版由打开任务页的浏览器领取排队项目。关闭页面后不会继续领取尚未开始的项目；已经到达服务器的命令仍按幂等契约完成。当前没有后台 Worker、消息队列或常驻调度器。

## 9. 三种角色的实际差异

| 能力 | 管理员 `admin` | 数据管理员 `data_manager` | 查看人员 `viewer` |
| --- | --- | --- | --- |
| 查看当前发布看板与已发布版本 | 可以 | 可以 | 可以 |
| 上传、确认解析、纠错、备注和完整校验 | 可以 | 可以 | 不可以 |
| 创建、暂停、恢复和重试批量审核任务 | 可以 | 可以 | 不可以 |
| 废弃本人活动草稿并重新解析来源文件 | 可以 | 可以 | 不可以 |
| 发布普通审核草稿 | 可以 | 可以 | 不可以 |
| 更改仅来源于未发布上传的草稿日期 | 可以 | 可以 | 不可以 |
| 从导入冲突强制重建活动草稿 | 可以 | 不可以 | 不可以 |
| 启动已发布跨日期移动 | 可以 | 不可以 | 不可以 |
| 审核已发布跨日期移动生成的目标草稿 | 可以 | 可以 | 不可以 |
| 最终生效或原子撤销已发布跨日期移动 | 可以 | 不可以 | 不可以 |
| 回滚、用户/角色、站点配置和内部审计管理 | 可以 | 不可以 | 不可以 |

查看人员仍能看到“数据审核”导航，但页面只显示只读权限边界，不提供上传、草稿或发布控件。查看人员的看板和版本接口不返回完整订单号、物流牌照或原始客户留言，只展示当前发布且允许查看的数据与备注。

## 10. 这次体验证明什么

上述手工步骤会启动真实的本地 FastAPI，并使用隔离 MySQL 测试库；它适合验证当前电脑上的实际交互，但不等同于最终全量门禁、正式库升级、备份恢复或服务器部署验收。

仓库中的 Playwright 主流程采用严格 API mock：它验证浏览器 UI 状态机、HTTP 命令载荷、CSRF、幂等键以及未处理请求会失败关闭，但不会启动 FastAPI 或 MySQL，因此不能称为真实 FastAPI + MySQL 全栈 E2E。

`agent_tools` 当前只是只读服务边界，没有接入具体模型，也没有 Agent 写数据能力。

## 11. 停止与重复体验

在前端和 API 两个窗口分别按 `Ctrl+C`。测试库账号、业务记录和 `data/raw/stage6-demo` 文件会保留，方便审计和重复查看；正式库不受影响。

再次运行时，请使用新的演示用户名。若要重新体验写流程，优先选择新的空闲测试日期；不要为了清理演示数据而执行整库删除或把脚本改指向正式库。
